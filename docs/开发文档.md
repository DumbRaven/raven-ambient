# Raven Ambient · 开发文档

给接手开发的人或 AI 助手看的完整技术说明。协作方式见 `协作风格.md`。

> **两份视觉版本**：本仓库是「明亮版」（纯白底、超大黑体标题、纯色大圆角卡片、黑色胶囊）。所有视觉改动都在 `src/skin-bold.css` 这一层覆盖，`src/styles.css` 一字未改。删掉 `src/main.tsx` 里 `import './skin-bold.css';` 那一行就退回原版。

## 一、这个项目是什么

一个**纯本地的声音唱片柜**。用户把本机的音乐和环境音拖进来，做成一面唱片墙；播放时音乐顺序循环、环境音同时叠加，音乐响起时环境音自动退让。

它还能**接管外部播放器**：QQ音乐、网易云这些程序的声音经由虚拟声卡流进来，本程序只保留环境音，并按音乐电平自动避让；歌名和封面从系统媒体会话（SMTC）读，唱盘上转的就是对方正在放的那张碟。

核心判断：**它是一个「收藏 + 播放」的东西，不是音乐播放器**。所以设计重心在唱片本身的质感（封套、彩胶、唱机）、收藏的动作（把唱片放上架）、和环境的氛围，而不是播放列表、均衡器、音效链。

目标平台顺序：Windows（已完成）→ macOS → Android → iOS。iOS 有已知风险，见第八节。

## 二、技术栈与运行方式

| 项 | 值 |
| --- | --- |
| 运行时 | Node 24 |
| 框架 | React 19 + TypeScript 5.9 |
| 构建 | Vite 7 |
| 桌面壳 | Electron 40（`electron/main.cjs`，70 行） |
| 打包 | electron-builder 26，输出 `release/win-unpacked` |
| 测试 | `node --test`，29 个文件 175 项 |
| 依赖 | `react` `react-dom` `lucide-react` `music-metadata` |

**关键架构事实：这是「纯 Web 应用 + 极薄的 Electron 外壳」。**

`electron/main.cjs` 只做几件事：开窗、加载 `dist/index.html`、设图标、关掉 Win11 的 Mica、等首帧再显示窗口、拒绝所有权限请求（`media`/`audioCapture` 除外，外部音乐要用）。渲染进程是 `sandbox: true` + `nodeIntegration: false` + **没有 preload**，所以业务代码里**没有任何一行 Node.js API**。

只有一个例外：`electron/now-playing.cjs` 会起一个常驻的 C# 小工具读系统媒体会话，但它与页面之间也没有 IPC 通道——页面是 `sandbox` 且无 preload，拿不到 `ipcRenderer`，所以方向反过来：主进程用 `executeJavaScript` 调页面里的 `window.__ravenNowPlaying(snapshot)` 推送快照，页面把动作写进 `window.__ravenNowPlayingOutbox`，主进程每 400ms 轮询取走。

这意味着 UI 和逻辑层是平台无关的，跨平台时不用重写。这是这个项目最值钱的架构决策，不要破坏它。

```bash
npm install
npm run dev              # 本地前端
npm run desktop          # 构建并启动 Electron
npm test                 # 全部测试
npm run build:nowplaying # 编译 SMTC 辅助程序（需系统自带 csc.exe）
npm run package:win      # 打包 Windows 目录版
npm run make:release     # 打免安装分发包 tar.gz（需先 package:win）
```

`electron/main.cjs` 支持 `RAVEN_DATA_DIR` 环境变量指定 userData 目录，用于隔离验证。

## 四、数据模型

### `RecordItem`（`src/records.ts`）

```ts
type RecordItem = {
  id: string; assetId: string; name: string; artist: string; description: string;
  category: 'music' | 'ambient';
  duration: number; format: string; size: number;
  color: string;                       // 唱片主色，彩胶取色的兜底
  coverId?: string;                    // 用户上传的封面（IndexedDB key）
  coverPreset?: string;                // 内置 SVG 封面 id
  fingerprint: string;                 // 去重用：name:size:lastModified
  volume: number; pan: number; warmth: number;
  duckDepth: number;                   // 避让深度，dB，0 表示不避让
};
```

### `Cabinet`（持久化到 localStorage key `raven-cabinet-v2`）

```ts
type Cabinet = {
  version: 2;
  records: RecordItem[];
  queue: string[];        // 音乐播放队列（record id，有序）
  ambience: string[];     // 同时流动的环境音（最多 8 路）
  muted: string[];        // 被单独按了暂停的环境音（record id），只在本次运行有效
  master: number; musicVolume: number;
  lineMode: boolean;      // 外部音乐模式：音乐交给别的播放器，本程序只留环境音
  lineVolume: number;     // 外部音乐的音量微调（0–100）
  order: 'sequence' | 'repeat-one' | 'shuffle';
  transition: 'off' | 'crossfade' | 'fade';
  theme: string; imageName: string;
};
```

**注意 `sanitizeCabinet()`**：所有读入的数据都要过这一层。它会补齐缺失字段、夹取越界值、丢弃无效记录。写测试数据时必须带 `assetId`、`size`、`fingerprint`，否则记录会被过滤掉——这个坑踩过。

还有两条容易踩的：

- **`coverPreset` 只对 `category === 'ambient'` 保留**，music 类会被清成 `undefined`。用 music 唱片测封面永远拿不到图。
- **`muted` 不进存档**：`cabinet-storage.ts` 的 `save()` 里写盘时一律清空 `muted: []`。运行时必须有这个字段（界面灰行、音频 `enabled` 都读它），但「哪几路被暂停」只在这一次运行里有效，重开软件回到全部流动。

### 存储布局

| 数据 | 位置 | key |
| --- | --- | --- |
| 唱片柜 JSON | localStorage | `raven-cabinet-v2` |
| 番茄钟设置 | localStorage | `raven-focus-settings-v1` |
| 番茄钟记录 | localStorage | `raven-focus-history-v1` |
| 音频 / 封面 / 背景 | IndexedDB `raven-ambient` / store `assets` | `assetId` / `cover-<id>` / `background` |

**所有存储访问都必须经过 `src/store.ts`**，不要直接碰 `localStorage` 或 `indexedDB`。原因见第八节。

## 五、核心模块

### 5.1 播放调度 `src/player.ts`

`RoomPlayer` 是唯一的状态源，向上通过 `listener` 回调推 `RoomStatus`。

```
start/pause/toggle         整体播放
toggleMusic/toggleAmbient  双通道独立开关
next(manual)/previous      切歌
playRecord(id)             点队列某首直接播
```

**`schedule()` 是核心**，用一条串行 `pending` Promise 链避免并发加载。每次调用递增 `revision`，异步步骤结束后用 `valid()` 检查是否已被新的调用取代——这是防止快速连点导致状态错乱的关键。

**双通道语义**：`wantsMusic() = running && musicOn && queue.length > 0`，`wantsAmbient()` 同理。两路都关时整体停止。

### 5.2 音频引擎 `src/audio.ts`

```
音乐文件 → <audio>×2 → MediaElementSource → musicGain ─┐
外部音乐 → getUserMedia(CABLE) → lineGain ────────────┤→ master → Compressor → destination
环境音   → BufferSource → filter → pan → gain → clip → duck ─┘
                                        ↑        ↑
                                   响度归一化   软限幅
```

**双唱盘设计**（第七批改造）：音乐用**两块 `<audio>` 元素轮换**，各自接一个 GainNode。交叉淡化时两块同时响、各自推增益，所以是真正的交叉淡化，不是靠一条增益曲线假装。

```ts
type Deck = { el: HTMLAudioElement; gain: GainNode; level: number; url?: string };
decks: Deck[];  activeDeck: number;
get music()      // 当前在响的那块
get spareDeck()  // 空着的那块
swapMusic(blob, mode, seconds)
```

`setInterval(tick, 80)` 每 80ms 推进一次：算音乐 RMS → 逐声部推进避让包络 → 写增益 → 更新状态。

**三条增益链各管一件事**：

| 节点 | 管什么 | 默认值 |
| --- | --- | --- |
| `musicGain` | 本地音乐音量 | `0.65`，之后由 `musicVolume` 接管 |
| `lineGain` | 外部音乐 | `0.65 × musicVolume/100 × lineVolume/100` |
| `master` | 总音量 | `0.65`，之后由 `master` 接管 |

外部音乐**和本地音乐吃同一档「音乐总音量」**，再乘它自己那档微调。早先 `lineGain` 是 1.0 满幅直通，比本地音乐响一倍，环境音被压得几乎听不见（实测差值 −9.2 dB，改后 −4.4 dB）。

**响度归一化**（`src/loudness.ts`）：每段环境音首次解码后测一次 RMS，按 −23 dB 基准算补偿增益，缓存在内存的 `Voice.loudness` 上，不进存档。最多补 15 dB、最多压 12 dB。

**软限幅**：每路声部在 `gain` 之后接一个 `WaveShaperNode`（`knee = 0.7`、`oversample: '2x'`、2048 点 tanh 曲线）。补上来的十几 dB 全在这里被削平，总线上就不会再顶。实测只有 0.05% 采样点触拐点，限幅前后 RMS 只差 0.4 dB。

**叠加补偿**：环境音基础系数 `0.55`。超过 3 路才按 `sqrt(3/路数)` 折回——八路全推满时总线会顶到限幅器，表现为「环境音加得越多，音乐反而越小」。一到三路不折。

### 5.2.1 外部音乐 `src/line-in.ts` + `src/now-playing.ts` + `electron/nowplaying/`

数据流：

```
QQ音乐/网易云 → 系统输出切到 CABLE Input → CABLE Output（虚拟麦克风）
             → 本程序 getUserMedia → 分析电平 → 环境音避让 → 混音 → 真实声卡
```

**设备不开放选择**，按 label 匹配 `/cable\s*output/i`，找不到再退回任何 VB-Audio 输入端点。不写死 `deviceId`：每台机器不同，重装驱动会变。

**三项音频处理必须在 `getUserMedia` 的约束里一次传齐**：

```ts
{ echoCancellation: false, noiseSuppression: false, autoGainControl: false, channelCount: 2 }
```

实测开着 AGC 时，10 倍音量差只量出 5.86 倍，侧链分析会被彻底破坏。事后在已有 track 上 `applyConstraints` 会抛 `OverconstrainedError`，改不了。

**歌名和封面**走 Windows SMTC（`electron/nowplaying/NowPlaying.cs`，用系统自带 `csc.exe` 编译，不需要 .NET SDK）。它每 700ms 查一次会话，只在内容变化时输出一行 JSON。

会话挑选按「可执行名优先级 + 播放状态」打分取最低分。**不能只看 label**：`Thumbnail` 不保证是专辑封面，Chrome 会话给的是 150×83 的视频缩略图。

**没有 IPC 通道**：页面是 `sandbox: true` 且无 preload，拿不到 `ipcRenderer`。所以方向反过来——主进程用 `executeJavaScript` 调页面里的 `window.__ravenNowPlaying(snapshot)` 推送，页面把动作（`toggle` / `next` / `previous` / `start` / `stop`）写进 `window.__ravenNowPlayingOutbox`，主进程每 400ms 轮询取走，转成 stdin 一行命令交给常驻的辅助程序。

**不做本地乐观更新**：播放器可能拒绝命令，按钮状态一律以辅助程序推回来的快照为准。

### 5.3 避让 `src/ducking.ts`

**这是项目里最有辨识度的功能，也是最容易被改坏的地方。**

从「开关式压低」改成了「包络式」：

```
音乐响起 → attackDelay 等待 → attackTime 淡入到目标深度
        → holdTime 保持 → releaseTime 淡出回到原音量
```

手感**按环境音封面类型绑定**，17 类各一套参数，不开放给用户：

| 类型 | attackTime | releaseTime | 理由 |
| --- | --- | --- | --- |
| forest / wind / snow / ocean | 1.4–1.8s | 2.1–2.4s | 大片绵延声，压快了像被掐住 |
| rain / fire / cafe / train | 0.7–1.0s | 1.3–1.6s | 中等，跟得上但不抢 |
| birds / insects / keyboard | 0.35–0.55s | 0.8–1.1s | 有明确起音，要快速让位 |

还有**迟滞防抖**：触发阈值 `on = threshold + hysteresis`，释放阈值 `off = threshold`，避免音量在阈值附近来回抽动。

深度单位是**分贝**（0–24 dB）。旧版是百分比，`percentToDb()` 负责迁移：旧「降低 65%」= 振幅乘 0.35 = −9.1 dB。

### 5.4 彩胶 `src/vinyl.ts`

从封面图**运行时取色**，生成唱片外圈的彩色胶盘：

1. canvas 采样 36×36
2. 跳过纯黑/纯白（纸边与阴影）
3. 按 `weight * sqrt(count)` 排序
4. 取最多 4 个色距 > 34 的主色
5. 结果按封面 URL 缓存

5 种压片工艺：`swirl` 晕染 / `marble` 云石 / `splatter` 泼溅 / `glow` 透光 / `halo` 光晕。

**工艺和配色按 `recordId + launchSeed` 的 FNV-1a 哈希决定**，不是每次渲染随机——否则翻页时封面会乱跳。同一次启动内固定，重启才换一批。

内圈 `.vinyl-label` 始终是封面，只有外圈是彩胶。

### 5.5 随机封套 `src/sleeves.ts`

没有封面的唱片，每次启动随机分到 6 种构图（晨光/地平线/拱门/轨道/涟漪/潮汐）× 8 组低饱和色调之一，同样由 `launchSeed + recordId` 哈希决定。

有用户封面时**永远优先**，随机封套只在没有封面时生效。

### 5.6 存储层 `src/store.ts` + `src/store-browser.ts`

```ts
getText(key) / setText(key, value) / removeText(key)
readAsset(key) / storeAsset(key, value?)
useStore(driver)   // 启动时替换实现
```

**业务代码只依赖这五个函数。** `localStorage` 和 `indexedDB` 在 `src/` 下只出现在 `store-browser.ts` 一个文件里。

driver 接口有个可选钩子 `mirrorText`：移动端 WebView 的 localStorage 可能被系统清掉，原生驱动可以在这里把文本快照镜像到文件系统。镜像失败不影响主流程。

### 5.7 番茄钟 `src/focus.ts` + `src/FocusRoom.tsx`

`focus.ts` 是纯逻辑，所有函数接收 `now` 时间戳，不自己读时钟——这样能单测。

状态机：`focus → break → focus → ... → longBreak`（每 `roundsBeforeLong` 轮）。

**`FocusRoom` 必须常驻挂载**，用 `<div hidden={view !== 'focus'}>` 包裹，不能用条件渲染——否则切走视图时组件卸载，计时重置。这个 bug 修过一次。

提示音用 Web Audio 现场合成（三声上行 784/1046.5/1318.5 Hz），不加载音频文件。

/* ---------- 第 N 批：功能名 ---------- */

## 八、跨平台

### 现状

UI 和逻辑层完全平台无关。业务代码里没有任何 Node.js API。

### 各平台成本

| 平台 | 结论 | 主要工作 |
| --- | --- | --- |
| macOS | 几乎零代码改动 | `electron-builder --mac`、补 `.icns`、调窗口习惯 |
| Android | 可行 | Capacitor 打包 + 改文件导入 + 改存储驱动 |
| iOS | 有已知风险 | 同上，另加后台音频验证 |

### 三个必须改的地方

**1. 文件导入**（`App.tsx` 的 `<input webkitdirectory>`）

`webkitdirectory` 在 Android WebView 和 iOS WKWebView **都不支持**。移动端没有「文件夹」概念，只能多选文件。这块必须重做。

**2. 存储**

`store-browser.ts` 换成原生驱动。移动端 WebView 的 localStorage 可能被系统清理，用 `mirrorText` 把快照写进文件系统。

**3. 后台音频（iOS 最硬的一条）**

iOS 上 **Web Audio 在后台会被挂起**，只有 `<audio>` / `<video>` 元素配 `UIBackgroundModes: audio` 能继续播。

这意味着锁屏后音乐可能还在，但**环境音叠加和动态避让大概率停掉**——恰好是这个软件最有辨识度的部分。

这是必须**先在真机验证**的事，不是留到最后调的点。如果确实不行，两条路：

- **A**：iOS 版降级——锁屏只保音乐，环境音在前台用。改动小，功能不一致。
- **B**：用 `AVAudioEngine` 重写混音层，保留全部功能。工作量大一个量级。

建议先走 A，用真实反馈决定要不要投 B。

## 九、开发环境注意事项

这些是实际踩过的坑，不是理论风险。

### 编码（最重要）

**禁止用 PowerShell 的 `Get-Content` / `Set-Content` 读写源码。**

它默认按 ANSI（GBK）解码 UTF-8。三字节中文字符会被解成双字节，写回时末字节变成 `?`。更阴险的是：中文字符的末字节（0x80–0xBF）会和**紧随其后的 ASCII 字节**组成一个 GBK 双字节字符，导致那个 ASCII **被吞掉**。

后果：字符串的闭合引号消失，语法全坏。这个项目因此损坏过 122 处，花了很多轮才修完。

**只能用 read / write / edit 工具，或 Node 的 `fs.readFileSync(..., 'utf8')`。**

### 命令

- `npm.cmd` 可用，`npm.ps1` 不可用（执行策略限制）
- `git` 需新装后重开进程，且新进程 PATH 不含它——要先把 Machine + User 的 PATH 拼起来
- `node --test tests/*.test.ts` 会 `spawn EPERM`，用 `npm.cmd test` 或单文件 `node tests/xxx.test.ts`
- `npx.cmd tsc` 会 MODULE_NOT_FOUND，用 `node node_modules/typescript/bin/tsc -b --force`
- **`pwsh` 内联 `node -e "...引号/中文/<div className=\"...\">..."` 必被解析器打断**（`ParserError` / `Invalid string escape`），一律写成 `.cjs` 文件再 `node` 执行；`node -c file.cjs` 可以先做语法检查。

### Electron 验证脚本

**必须隔离 userData**，否则会写进用户真实数据：

```js
app.setPath('userData', path.join(os.tmpdir(), 'raven-test-' + Date.now()));
```

`ELECTRON_RUN_AS_NODE` 环境变量会让 `electron.exe` 退化成纯 Node，报 `Cannot read properties of undefined (reading 'setPath')`。用 `Start-Process` 并显式清除该变量。

标准启动模板：

```powershell
$root = 'C:\path\to\Vibe-bold'   # 换成你本地的仓库路径
$psi = New-Object System.Diagnostics.ProcessStartInfo
$psi.FileName = "$root\node_modules\electron\dist\electron.exe"
$psi.Arguments = "$Script --no-sandbox --disable-gpu-sandbox --disable-renderer-backgrounding --disable-background-timer-throttling"
$psi.WorkingDirectory = $root
$psi.UseShellExecute = $false
$psi.RedirectStandardOutput = $true
$psi.RedirectStandardError = $true
[void]$psi.EnvironmentVariables.Remove('ELECTRON_RUN_AS_NODE')
$p = [System.Diagnostics.Process]::Start($psi)
$outTask = $p.StandardOutput.ReadToEndAsync()
$errTask = $p.StandardError.ReadToEndAsync()
if (-not $p.WaitForExit($TimeoutMs)) { $p.Kill() }
```

`--disable-renderer-backgrounding` 等三个开关是必需的：`requestAnimationFrame` 在后台窗口会被节流，采不到波形数据。

**要验证外部音乐相关功能，必须走真实主进程** `require('./electron/main.cjs')`，因为 `loadFile(dist/index.html)` 不含 now-playing 桥，底部控制器会一直 `disabled`。

### 隐藏窗口截图的坑

- 隐藏窗口**不跑 rAF**，CSS `transition` 会冻结在起始值。截图前必须 `insertCSS('*,*::before,*::after{transition:none!important;animation:none!important}')` 再 `invalidate()`。
- 但读动画参数必须在注入之前，否则读到 `none`。
- `animation-fill-mode: both` 会让元素永久停在 `from{opacity:0}`。
- 窗口放到屏幕外（`x:-2000`）Chromium 判定不可见，不真正渲染，截图是空盘。必须 `show: true` 且在屏幕内，并且显式 `win.show(); win.focus();`，`capturePage()` 前 `win.webContents.invalidate()`。
- `capturePage(box)` 区域超出窗口或 0 宽高会写出 0 字节文件。

### 打包

`npm.cmd run package:win` 报 `EBUSY: resource busy or locked, open 'release\win-unpacked\Raven Ambient Bold.exe'`（栈在 `editWindowsResources`）时，产物会是坏的：exe 的 `FileDescription` 退化成 `Electron`、大小变成 213,977,088（正常 214,039,552）。

**唯一有效的解法**是先关掉所有实例、删掉旧目录再重跑：

```powershell
Get-Process -Name 'Raven Ambient*' | Stop-Process -Force
Remove-Item -LiteralPath 'release\win-unpacked' -Recurse -Force
npm.cmd run package:win
```

### 校验 asar 内容

```js
const buf = fs.readFileSync(asarPath);
const headerSize = buf.readUInt32LE(12);
const dataStart = 8 + buf.readUInt32LE(4);
const header = JSON.parse(buf.slice(16, 16 + headerSize));
// 取某个文件：buf.slice(dataStart + Number(f.offset), dataStart + Number(f.offset) + Number(f.size))
```

**`offset` / `size` 是字符串，必须 `Number()`**，否则 `ds + f.offset` 会做字符串拼接，`slice` 出来长度为 0。

Vite 会压缩函数名与属性名（`lineInError` 查不到、`0.55` 变成 `.55`），所以校验要查**函数体内的中文字符串**或带前缀的片段，不能只查裸标识符。

### 分发体积

Electron 的运行时有 260 MB 左右，我们自己的代码只有 1.2 MB。能压的地方和不能碰的地方：

| 项 | 做法 | 省下 | 位置 |
|---|---|---|---|
| 语言包 | `build.electronLanguages` 只留 `zh-CN`、`en-US` | 44 MB | `package.json` |
| WebGPU 着色器编译器 | 打包后删 `dxcompiler.dll`、`dxil.dll` | 26 MB | `scripts/package-win.cjs` |
| 下载包格式 | zip（deflate 43%）换成整包 `tar.gz`（41%） | 24 MB | `scripts/make-release.cjs` |

**不要动 `vk_swiftshader.dll`（5.4 MB）和 `vulkan-1.dll`（0.9 MB）**：这是没有独显或显卡驱动异常时的软件渲染兜底，删了会让界面直接白屏。同理 `d3dcompiler_47.dll`（4.5 MB）是 ANGLE 编译 D3D11 着色器用的，WebGL 依赖它。`LICENSES.chromium.html`（15 MB）是分发必须带的许可证文本。

裁 `dxcompiler.dll` 的依据：本项目只用 Canvas 2D 与 CSS 渐变，WebGL 走 ANGLE→D3D11→`d3dcompiler_47.dll`，`navigator.gpu` 在打包产物里是 `false`。验证方式是把两个 dll 改名后跑一遍 Canvas 2D 取色像素、WebGL 着色器编译、CSS 渐变、Web Audio，逐项比对全部一致。

`tar.gz` 用 `tar -c -z -f`，Windows 10 1803 之后系统自带 bsdtar，解压不需要用户装 7-Zip；分发包里附一个 `解压后运行我.cmd`（`cd /d "%~dp0"` + `tar -xf ...`）让用户双击即可。

**为什么不用压缩率更高的 `.tar.xz`**：`tar -c -J -f` 能把包压到 82 MB，但 bsdtar 内置的 liblzma 在 GitHub Actions 的 runner 上压 260 MB 会以 `0xC0000005`（访问冲突 / 段错误）崩掉——本地机器每次都成功，CI 上每次都失败，属于运行环境相关的编码器 bug，不是我们的用法问题。发版流程不能押在一个会随机崩的编码器上，所以退 28 MB 换稳定。如果以后一定要把包压小，正确做法是在 runner 上单独装一个 `xz.exe` 并 `xz -9e -T1`，而不是用 `tar -J`。

## 十二、给接手者的话

这个项目的代码量不大（约 2000 行 TypeScript 加 2600 行样式），但**细节密度很高**。很多地方看起来可以简化，实际上是为某个具体问题写的。

改之前先读 `协作风格.md`。遇到不理解的实现，先查 `tests/` 里有没有对应的测试——通常测试注释里写了为什么。

最后：**用户能看出动画的差别**。切歌动画改过三轮，避让手感调过多轮，圆角从 `squircle` 换到 `superellipse(1.2)` 又微调过。不要用「差不多」交付视觉和手感。
