# 重构交接（2026-11-16）

给接手这个仓库的人看。

**这份文档记得不是「现在是什么样子」，而是「为什么是这个样子」。** 前者去读代码，代码永远是对的；后者只在人的脑子里，人不在了就没了。

所以下面每一条都满足两个条件之一：要么是**代码里表达不出来的取舍理由**，要么是**花了代价才换来的结论**（通常是「看起来该这么改，改完发现不行」）。凡是能靠读代码或读 `git log` 得到的，这里一律不写——那种内容会腐烂，而腐烂的文档比没有文档更危险（`6cf9c89` 删掉的那两份就死于此）。

## 二、最重要的一件事：视觉门禁

`tsc` 和单测**完全看不见**视觉回归。阴影浅 2px、断点留白从 24 变 32、黑胶滑出角度偏 3 度——这些都能通过类型检查和全部测试。这一轮拆了 8000 行 CSS、删了 493 行规则，如果没有门禁，等于蒙眼改。

### 两个门禁，抓的东西不一样

- **像素基线**（`tools/probe/baseline.cjs` → 28 张 PNG，`baseline-diff.py` 比对）：抓「看得见的位置、颜色、形状变了」。覆盖 2 个尺寸（680×980 / 440×860）× 11 个状态 + 6 张全屏/透明形态。
- **计算样式快照**（`tools/probe/styles.cjs` → 12 份，约 **274 万个属性**，`style-diff.mjs` 比对）：抓「声明被丢弃但视觉暂未体现」。

**样式快照抓到过两个像素图完全看不出来的真 bug**：

1. 令牌替换脚本的正则 `#ffffff` 命中了 `#ffffff1f` 的前六个字符，写出非法的 `var(--bold-bg)1f`——**整条声明被浏览器丢弃**，元素退回初始值。像素上看不出差别，因为那条声明恰好是修饰性的。
2. `container-type: size` 被误删，导致拼贴版所有 `cqw` 单位的字号失效。

这两个都证明了一件事：**只有像素基线是不够的**。

### 让门禁真的可靠，需要钉死六件东西

这部分耗了十几轮才稳定，改动探针前先读 `tools/probe/baseline.cjs` 顶部注释与 `harness.cjs`。摘要：

1. `force-device-scale-factor = 1` 必须在 `require('./harness.cjs')` **之前**执行（本机 150% 缩放会把 680×980 截成 1020×1470，换台机器就全崩，而且不报错）。
2. 指针停 park 位（`PARK_POINTER = {x:1,y:1}`），否则 hover 那张刚移上去就被挪走。拍 hover 那张要传 `park: false`。
3. 随机源必须在页面脚本运行**之前**注入（走 CDP `Page.addScriptToEvaluateOnNewDocument`），`executeJavaScript` 太晚——`sleeves.ts` 的 `launchSeed` 在模块求值时就算完了。
4. `Date` 要整个替换（`class FixedDate extends RealDate`），只钉 `Date.now` 冻不住 `LayerStack` 的时钟。
5. 动画“跑一次就停”：注入 `animation-iteration-count:1; animation-fill-mode:forwards; animation-duration:0.001s`。**不能用 `animation:none`**（会清掉 fill-mode，布局错位），也不能用 `a.pause()`（会被 `animation-play-state` 覆盖回去）。
6. 播放态要同时钉三处：`HTMLMediaElement.currentTime` getter、`BaseAudioContext.currentTime`、40 根波形条的内联 `--h`。素材必须是 **60 秒**等幅正弦——3 秒的会在截图窗口内播完，触发 `onEnded` 自动接下一首。

**噪声判定必须两个条件同时成立**：`NOISE_RATIO = 0.0002` **且** `NOISE_DELTA = 1`。只看面积会漏掉“小图标换了颜色”，只看差值会漏掉“整块挪了 1px”。

### 一个必须先记住的坑

**探针加载的是 `dist/index.html`，不是 `src/`。**（`tools/probe/harness.cjs` 里 `win.loadFile(path.join(ROOT, 'dist', 'index.html'))`）

改完 CSS 不跑 `npm run build` 就拍快照，比出来是「12 份完全一致」的假绿灯。第一次就踩了这个坑，白高兴一场。

## 三、十条花代价换来的结论

按「如果不写下来，下一个人一定会重犯」排序。

### 1. 「切页掉帧」是伪问题，而且为了修它会真把页面搞坏

追了三层（`clip-path` 圆扩散、`will-change`、高度动画），每层都被下一层推翻。最后在真实窗口里测：**6.2–6.3ms、约 160fps、零丢帧**。之前那个「30.1ms → 21.8ms」的改进，是把冷启动成本算进了对照组。

**离屏渲染把 `requestAnimationFrame` 钉在 16.67ms（忙时 20ms）**，真实窗口是 6.25ms。所以离屏数据只能做同环境相对比较，**绝不能当“用户看到多少 ms”**。

更重要的：`.view-stage` 上加 `contain: paint` 或 `transform: translateZ(0)` 会让页内 10 处 `position: fixed` 浮层重新定位 → **整页变空白**（实测差异 8294400 像素 = 满屏）。这两条是天然的“性能优化”直觉，加了一定出事。

### 2. 双向同名 IPC 通道是个陷阱

一开始 `stage:command` / `focus:action` 两个方向共用一个名字，白名单是两份（`SEND` / `RECEIVE`）且严格不相交。结果是：主进程往回推时被 `RECEIVE` 判掉，**监听器根本没注册**，桌面窗第一次点切歌就失效——而 `viaIpc` 已经被置 true，连轮询旧路也关了。

审计给了两个方案：加 `BOTH` 集合，或退回 `executeJavaScript`。**两个都该拒**：前者等于放弃“页面不能伪造主进程消息”这道防线（那正是分成两份名单的全部意义），后者等于放弃 IPC。

正确的做法是**把双向通道拆成两条单向通道**：页面发出仍叫 `stage:command`，主进程回推改名 `stage:press`。名字分开，防线保住。

### 3. 「不生效的 CSS 规则」要么修好，要么删掉，不要搬来搬去

`@media (max-width:440px)` 里的 `.record-grid { column-gap:14px; row-gap:24px }` 写在 `rooms.css`，被更晚 `@import` 的 `modern.css` 基础规则整条压掉，**从 v0.3.0 起从未生效**。

把它搬到正确位置后实测像素差异 = 卡片窄 0.5px、第二行下移 2px。但这两个数值**从没被任何截图验证过**。用未验证的设计去顶掉用户正在看的 13/22，收益只有 1px、感知不到。

最终决定：**删掉 14/24，只留真正需要且真生效的 `padding: 0`**。

同一类判断还有几处：`.view-tabs > button { padding: 8px 10px }` 永远输给 `modern.css` 的 `8px 8px`，删；`.theater-loop` 系列在 TSX 里零命中，删。

### 4. 状态类清单要靠 grep 核，不能靠记

`AGENTS.md` 以前写着「`inspected` 是触屏唯一的展开路径，不能写成 `transform: none`」。**这是错的**：`inspected` 在 `src/**` 里零引用，触屏展开的真实路径是 `data-flip` 属性（`RecordCard.tsx:50` 输出，样式在 `src/skin/rooms.css:331-332`）。`styles.css:5` 里那条 `.record-card.inspected` 从写下来那天起就没命中过。

同样，「`.queue-item.drop-before::before` 是拖拽插入线」也已过时——`MusicQueue.tsx` 改成了浮起卡片 + `settling`/`settled` 两段落地动画，`drop-before` 在 TSX 里零引用。

**教训：凡是「某个类名/变量有没有人用」的判断，一律 grep 一遍再用，不要从记忆里取。**

### 5. `commit` 与 `change` 是两种语义，别混用

`change()` 是 `try { commit(...) } catch { /* notice already shown */ }`——**吞异常、返回 void**；`commit()` 会抛。

这一对语义恰好对应两种场景：
- 用户主动操作、失败必须让他知道 → 用 `commit`（编辑弹窗保存失败要留在弹窗里显示错误，不能关窗假装成功）；
- 后台/次要操作、失败只提示一下 → 用 `change`。

踩过的坑：`clearBackground` 写成「先删资产 → 再 `change()` 存文本」，而 `change` 吞了异常 → 留下“有名字没图”的坏状态。改成**先 `commit` 再动资产**。

还有：`commit` 要求完整 `Cabinet`，不是 `Partial`。写 `commit({ records: ... })` 会报 `TS2345: missing properties version, queue, ambience, master, and 11 more`，必须写 `commit({ ...cabinetRef.current, records: ... })`。

### 6. 一个模块级单例和调用方自己 `new` 的实例，不是同一个对象

`cabinet-storage.ts` 里有个模块级 `const storage = new CabinetStorage()` 供 `restoreSalvage()` / `adoptEmptyCabinet()` 用，但 `App.tsx` 写盘用的是 `useRef(new CabinetStorage())`。

结果：「不要了，从空柜开始」的解锁操作作用在**别人的实例**上——横幅消失了、保存永久失败，而且没有任何报错。

修法不是“统一用一个单例”（那会把测试全搞脏），而是**让这两个函数接收实例参数**。凡是“模块级持有状态 + 调用方自建实例”的组合，都要检查这一点。

### 7. 恢复类功能必须有「已经试过了」的标记

「恢复原文件」的实现是把读不出来的那份原文**写回主键**——重载后必然再次读坏 → 横幅又出现 → 再点 → 再重载，**无限循环**。

修法：写回时同时记 `RESTORED_KEY`，读取时用 `alreadyRestored(current)` 判断，`CabinetLoad` 带出 `retried: true`，界面据此藏掉恢复按钮。

**凡是「把 A 复制到 B 然后指望 B 变好」的恢复逻辑，都要问一句：如果 B 本来就是坏的，用户点第二次会发生什么。**

### 8. 备份失败时最需要提示，而不是最不需要

横幅本来的显示条件是 `if (loaded.broken) setSalvage(loaded.salvage)`——而 `salvage` 字段的意思是**备份有没有写成**。备份失败（配额满、隐私模式）时横幅跟着不消失……

反了。备份失败恰恰是**最需要**提示的时候：数据读坏了、备份也没写成、保存已暂停，用户此刻手动操作一下就可能把原文盖掉。

正确写法：`if (loaded.broken) { setSalvage(true); setSalvageReason(loaded.reason); }`——**损坏就是损坏，备份成功与否是另一回事**。

### 9. 错误必须按来源分流，不能都往一个桶里扔

音频引擎里，环境音起不来、音乐文件读不出、试听失败——三种完全不同的失败。原来全走 `onError`，导致：一张环境音文件被删 → 播放器认为整体失败 → `return` → **连本来好好的音乐也不响了**。

现在：
- 环境音部分失败 → 走单独的 `onAmbientLost` 通道（“这几张起不来了”，其它照响）；
- 环境音**全部**失败才抛；
- 音乐文件读不出 → `pauseMusic()` + `skipBroken()`，**不能调 `this.pause()`**（它走 `engine.stopAll()`，会连环境音一起停掉）。

同类问题：试听坏文件时 `engine.preview` 内部 `catch` 会调 `stopPreview()`，而那**同步**触发 `previewEnded` → `restoreAfterPreview`，可那一刻 `previewSwitching` 还是 `true`，恢复被跳过 → **背景音乐永久停掉**，只能用户自己再点一次播放。

### 10. “哪一张在响”和“有没有在响”是两个问题

`status.playing` 是**引擎级**语义（任意一路在响就算 true）。三张环境音坏一张，它仍是 `true` → 那张的封套照样转、队列里照样写“循环叠加”，用户以为它在响只是听不见。

加了 `status.ambientIds`（真的起了声部的 id 列表）之后才对。而全坏时 `running` 也要跟着下来——否则界面挂着“正在播放”却满屏无声，用户下一步一定按播放键，而 `running === true` 时那个键走 `pause()`，按下去只是把已经起不来的环境音又停一遍，屏幕纹丝不动，怎么按都回不到能播的状态。

## 五、明确「不改」的地方（附理由）

这些看起来像 bug 或死代码，但**改了一定出事**，或者改了没意义：

- **`.pressing-*` 的彩胶配色**：覆盖层写 `background` / `transform` 简写会整片盖掉它。曾经发生过。
- **`.cabinetMix()` 里 `ducking: true` 写死**：`RecordNotes.tsx` 让用户逐张把避让幅度滑到 0 并告诉他「这张唱片保持原音量」，避让是**逐张**由 `duckDepth` 控制的；`Mix.ducking` 是没暴露在界面上的全局开关。改成读 `cabinet.ducking` 反而会让旧存档里的 `false` 生效，而用户从没在界面上关过它。
- **`src/ticket.ts` 的 `if (!Number.isNaN(at.getTime()))`**：看着恒真，但 `new Date(1e300).getTime()` 返回 `NaN`，`getFullYear()` 也是 `NaN`，票根会印出 `NaN`。这是有效防御。
- **`app.asar` 里 `.toggle span` 那个空 `<span />`**：它是开关的圆点本体，`translateX(18px)` 靠它移动。删了开关就只剩一片没有把手的底色。
- **`lineLive` 之外的 `lineInput === 0` 不能当作「没接上」**：没声音的时候它本来就是 0。判断接没接上要看 `lineLive`。
- **`defaultTracks` / `defaultMix` 生产代码零引用**：5 个测试文件拿它们当混音平衡与避让曲线的 fixture。**不要当死代码删掉。**

### 已推翻的一条（2026-11-17）

- **`src/video-palette.ts` 的色距用字符编码差**——原来记在这里，理由是「换成真实色距会改变视频壁纸抽到的四个色，用户选保持现状」。**推翻了。** 那条判据比的是十六进制字符串里对应字符的编码差（`'f'` 与 `'1'` 差 59），而深色画面里排前面的几个桶往往是同色相近邻（`#1a1314` / `#281811` / `#2f2929`，明度只差 1~3%），字符差只有 1~3，永远过不了 34 那道坎——**164 个视频里 62 个只取回一个色**，配色面板「挑一个」那一栏就只剩一块可点（用户 2026-11-17 报的现象）。
  - 改法：两份重复实现合并成 `src/vinyl.ts` 的 `pickPalette()`，封面与视频共用同一份分桶、排序、去重（真实 RGB 色距 > 34）。提交 `7ca903e`。
  - 实测：旧判据出 1 个 62 / 出 4 个 13；新判据出 1 个 **0** / 出 4 个 **142**。
  - 教训：**「用户已经在看的东西不要动」这条理由只在收益小的时候成立**。这里收益是 62 个视频从「没法挑」变成「能挑」，远大于四个色号变化的成本。下一个人如果又想往回改，先去看 `tests/video-palette.test.ts` 的注释。
