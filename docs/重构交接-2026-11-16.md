## 二、最重要的一件事：视觉门禁

`tsc` 和单测**完全看不见**视觉回归。阴影浅 2px、断点留白从 24 变 32、黑胶滑出角度偏 3 度——这些都能通过类型检查和全部测试。这一轮拆了 8000 行 CSS、删了 493 行规则，如果没有门禁，等于蒙眼改。

### 两个门禁，抓的东西不一样

- **像素基线**（`tools/probe/baseline.cjs` → 28 张 PNG，`baseline-diff.py` 比对）：抓「看得见的位置、颜色、形状变了」。覆盖 2 个尺寸（680×980 / 440×860）× 11 个状态 + 6 张全屏/透明形态。
- **计算样式快照**（`tools/probe/styles.cjs` → 12 份，约 **274 万个属性**，`style-diff.mjs` 比对）：抓「声明被丢弃但视觉暂未体现」。

**样式快照抓到过两个像素图完全看不出来的真 bug**：

1. 令牌替换脚本的正则 `#ffffff` 命中了 `#ffffff1f` 的前六个字符，写出非法的 `var(--bold-bg)1f`——**整条声明被浏览器丢弃**，元素退回初始值。像素上看不出差别，因为那条声明恰好是修饰性的。
2. `container-type: size` 被误删，导致拼贴版所有 `cqw` 单位的字号失效。

这两个都证明了一件事：**只有像素基线是不够的**。

### 让门禁真的可靠，需要钉死六件东西

这部分耗了十几轮才稳定，改动探针前先读 `tools/probe/baseline.cjs` 顶部注释与 `harness.cjs`。摘要：

1. `force-device-scale-factor = 1` 必须在 `require('./harness.cjs')` **之前**执行（本机 150% 缩放会把 680×980 截成 1020×1470，换台机器就全崩，而且不报错）。
2. 指针停 park 位（`PARK_POINTER = {x:1,y:1}`），否则 hover 那张刚移上去就被挪走。拍 hover 那张要传 `park: false`。
3. 随机源必须在页面脚本运行**之前**注入（走 CDP `Page.addScriptToEvaluateOnNewDocument`），`executeJavaScript` 太晚——`sleeves.ts` 的 `launchSeed` 在模块求值时就算完了。
4. `Date` 要整个替换（`class FixedDate extends RealDate`），只钉 `Date.now` 冻不住 `LayerStack` 的时钟。
5. 动画“跑一次就停”：注入 `animation-iteration-count:1; animation-fill-mode:forwards; animation-duration:0.001s`。**不能用 `animation:none`**（会清掉 fill-mode，布局错位），也不能用 `a.pause()`（会被 `animation-play-state` 覆盖回去）。
6. 播放态要同时钉三处：`HTMLMediaElement.currentTime` getter、`BaseAudioContext.currentTime`、40 根波形条的内联 `--h`。素材必须是 **60 秒**等幅正弦——3 秒的会在截图窗口内播完，触发 `onEnded` 自动接下一首。

**噪声判定必须两个条件同时成立**：`NOISE_RATIO = 0.0002` **且** `NOISE_DELTA = 1`。只看面积会漏掉“小图标换了颜色”，只看差值会漏掉“整块挪了 1px”。

### 一个必须先记住的坑

**探针加载的是 `dist/index.html`，不是 `src/`。**（`tools/probe/harness.cjs` 里 `win.loadFile(path.join(ROOT, 'dist', 'index.html'))`）

改完 CSS 不跑 `npm run build` 就拍快照，比出来是「12 份完全一致」的假绿灯。第一次就踩了这个坑，白高兴一场。

## 三、十条花代价换来的结论

按「如果不写下来，下一个人一定会重犯」排序。

### 1. 「切页掉帧」是伪问题，而且为了修它会真把页面搞坏

追了三层（`clip-path` 圆扩散、`will-change`、高度动画），每层都被下一层推翻。最后在真实窗口里测：**6.2–6.3ms、约 160fps、零丢帧**。之前那个「30.1ms → 21.8ms」的改进，是把冷启动成本算进了对照组。

**离屏渲染把 `requestAnimationFrame` 钉在 16.67ms（忙时 20ms）**，真实窗口是 6.25ms。所以离屏数据只能做同环境相对比较，**绝不能当“用户看到多少 ms”**。

更重要的：`.view-stage` 上加 `contain: paint` 或 `transform: translateZ(0)` 会让页内 10 处 `position: fixed` 浮层重新定位 → **整页变空白**（实测差异 8294400 像素 = 满屏）。这两条是天然的“性能优化”直觉，加了一定出事。

### 2. 双向同名 IPC 通道是个陷阱

一开始 `stage:command` / `focus:action` 两个方向共用一个名字，白名单是两份（`SEND` / `RECEIVE`）且严格不相交。结果是：主进程往回推时被 `RECEIVE` 判掉，**监听器根本没注册**，桌面窗第一次点切歌就失效——而 `viaIpc` 已经被置 true，连轮询旧路也关了。

审计给了两个方案：加 `BOTH` 集合，或退回 `executeJavaScript`。**两个都该拒**：前者等于放弃“页面不能伪造主进程消息”这道防线（那正是分成两份名单的全部意义），后者等于放弃 IPC。

正确的做法是**把双向通道拆成两条单向通道**：页面发出仍叫 `stage:command`，主进程回推改名 `stage:press`。名字分开，防线保住。

### 3. 「不生效的 CSS 规则」要么修好，要么删掉，不要搬来搬去

`@media (max-width:440px)` 里的 `.record-grid { column-gap:14px; row-gap:24px }` 写在 `rooms.css`，被更晚 `@import` 的 `modern.css` 基础规则整条压掉，**从 v0.3.0 起从未生效**。

把它搬到正确位置后实测像素差异 = 卡片窄 0.5px、第二行下移 2px。但这两个数值**从没被任何截图验证过**。用未验证的设计去顶掉用户正在看的 13/22，收益只有 1px、感知不到。

最终决定：**删掉 14/24，只留真正需要且真生效的 `padding: 0`**。

同一类判断还有几处：`.view-tabs > button { padding: 8px 10px }` 永远输给 `modern.css` 的 `8px 8px`，删；`.theater-loop` 系列在 TSX 里零命中，删。

### 4. 状态类清单要靠 grep 核，不能靠记

`AGENTS.md` 以前写着「`inspected` 是触屏唯一的展开路径，不能写成 `transform: none`」。**这是错的**：`inspected` 在 `src/**` 里零引用，触屏展开的真实路径是 `data-flip` 属性（`RecordCard.tsx:50` 输出，样式在 `src/skin/rooms.css:331-332`）。`styles.css:5` 里那条 `.record-card.inspected` 从写下来那天起就没命中过。

同样，「`.queue-item.drop-before::before` 是拖拽插入线」也已过时——`MusicQueue.tsx` 改成了浮起卡片 + `settling`/`settled` 两段落地动画，`drop-before` 在 TSX 里零引用。

**教训：凡是「某个类名/变量有没有人用」的判断，一律 grep 一遍再用，不要从记忆里取。**

### 5. `commit` 与 `change` 是两种语义，别混用

`change()` 是 `try { commit(...) } catch { /* notice already shown */ }`——**吞异常、返回 void**；`commit()` 会抛。

这一对语义恰好对应两种场景：
- 用户主动操作、失败必须让他知道 → 用 `commit`（编辑弹窗保存失败要留在弹窗里显示错误，不能关窗假装成功）；
- 后台/次要操作、失败只提示一下 → 用 `change`。

踩过的坑：`clearBackground` 写成「先删资产 → 再 `change()` 存文本」，而 `change` 吞了异常 → 留下“有名字没图”的坏状态。改成**先 `commit` 再动资产**。

还有：`commit` 要求完整 `Cabinet`，不是 `Partial`。写 `commit({ records: ... })` 会报 `TS2345: missing properties version, queue, ambience, master, and 11 more`，必须写 `commit({ ...cabinetRef.current, records: ... })`。

### 6. 一个模块级单例和调用方自己 `new` 的实例，不是同一个对象

`cabinet-storage.ts` 里有个模块级 `const storage = new CabinetStorage()` 供 `restoreSalvage()` / `adoptEmptyCabinet()` 用，但 `App.tsx` 写盘用的是 `useRef(new CabinetStorage())`。

结果：「不要了，从空柜开始」的解锁操作作用在**别人的实例**上——横幅消失了、保存永久失败，而且没有任何报错。

修法不是“统一用一个单例”（那会把测试全搞脏），而是**让这两个函数接收实例参数**。凡是“模块级持有状态 + 调用方自建实例”的组合，都要检查这一点。

### 7. 恢复类功能必须有「已经试过了」的标记

「恢复原文件」的实现是把读不出来的那份原文**写回主键**——重载后必然再次读坏 → 横幅又出现 → 再点 → 再重载，**无限循环**。

修法：写回时同时记 `RESTORED_KEY`，读取时用 `alreadyRestored(current)` 判断，`CabinetLoad` 带出 `retried: true`，界面据此藏掉恢复按钮。

**凡是「把 A 复制到 B 然后指望 B 变好」的恢复逻辑，都要问一句：如果 B 本来就是坏的，用户点第二次会发生什么。**

### 8. 备份失败时最需要提示，而不是最不需要

横幅本来的显示条件是 `if (loaded.broken) setSalvage(loaded.salvage)`——而 `salvage` 字段的意思是**备份有没有写成**。备份失败（配额满、隐私模式）时横幅跟着不消失……

反了。备份失败恰恰是**最需要**提示的时候：数据读坏了、备份也没写成、保存已暂停，用户此刻手动操作一下就可能把原文盖掉。

正确写法：`if (loaded.broken) { setSalvage(true); setSalvageReason(loaded.reason); }`——**损坏就是损坏，备份成功与否是另一回事**。

### 9. 错误必须按来源分流，不能都往一个桶里扔

音频引擎里，环境音起不来、音乐文件读不出、试听失败——三种完全不同的失败。原来全走 `onError`，导致：一张环境音文件被删 → 播放器认为整体失败 → `return` → **连本来好好的音乐也不响了**。

现在：
- 环境音部分失败 → 走单独的 `onAmbientLost` 通道（“这几张起不来了”，其它照响）；
- 环境音**全部**失败才抛；
- 音乐文件读不出 → `pauseMusic()` + `skipBroken()`，**不能调 `this.pause()`**（它走 `engine.stopAll()`，会连环境音一起停掉）。

同类问题：试听坏文件时 `engine.preview` 内部 `catch` 会调 `stopPreview()`，而那**同步**触发 `previewEnded` → `restoreAfterPreview`，可那一刻 `previewSwitching` 还是 `true`，恢复被跳过 → **背景音乐永久停掉**，只能用户自己再点一次播放。

### 10. “哪一张在响”和“有没有在响”是两个问题

`status.playing` 是**引擎级**语义（任意一路在响就算 true）。三张环境音坏一张，它仍是 `true` → 那张的封套照样转、队列里照样写“循环叠加”，用户以为它在响只是听不见。

加了 `status.ambientIds`（真的起了声部的 id 列表）之后才对。而全坏时 `running` 也要跟着下来——否则界面挂着“正在播放”却满屏无声，用户下一步一定按播放键，而 `running === true` 时那个键走 `pause()`，按下去只是把已经起不来的环境音又停一遍，屏幕纹丝不动，怎么按都回不到能播的状态。

## 五、明确「不改」的地方（附理由）

这些看起来像 bug 或死代码，但**改了一定出事**，或者改了没意义：

- **`.pressing-*` 的彩胶配色**：覆盖层写 `background` / `transform` 简写会整片盖掉它。曾经发生过。
- **`.cabinetMix()` 里 `ducking: true` 写死**：`RecordNotes.tsx` 让用户逐张把避让幅度滑到 0 并告诉他「这张唱片保持原音量」，避让是**逐张**由 `duckDepth` 控制的；`Mix.ducking` 是没暴露在界面上的全局开关。改成读 `cabinet.ducking` 反而会让旧存档里的 `false` 生效，而用户从没在界面上关过它。
- **`src/ticket.ts` 的 `if (!Number.isNaN(at.getTime()))`**：看着恒真，但 `new Date(1e300).getTime()` 返回 `NaN`，`getFullYear()` 也是 `NaN`，票根会印出 `NaN`。这是有效防御。
- **`app.asar` 里 `.toggle span` 那个空 `<span />`**：它是开关的圆点本体，`translateX(18px)` 靠它移动。删了开关就只剩一片没有把手的底色。
- **`lineLive` 之外的 `lineInput === 0` 不能当作「没接上」**：没声音的时候它本来就是 0。判断接没接上要看 `lineLive`。
- **`defaultTracks` / `defaultMix` 生产代码零引用**：5 个测试文件拿它们当混音平衡与避让曲线的 fixture。**不要当死代码删掉。**

### 已推翻的一条（2026-11-17）

- **`src/video-palette.ts` 的色距用字符编码差**——原来记在这里，理由是「换成真实色距会改变视频壁纸抽到的四个色，用户选保持现状」。**推翻了。** 那条判据比的是十六进制字符串里对应字符的编码差（`'f'` 与 `'1'` 差 59），而深色画面里排前面的几个桶往往是同色相近邻（`#1a1314` / `#281811` / `#2f2929`，明度只差 1~3%），字符差只有 1~3，永远过不了 34 那道坎——**164 个视频里 62 个只取回一个色**，配色面板「挑一个」那一栏就只剩一块可点（用户 2026-11-17 报的现象）。
  - 改法：两份重复实现合并成 `src/vinyl.ts` 的 `pickPalette()`，封面与视频共用同一份分桶、排序、去重（真实 RGB 色距 > 34）。提交 `7ca903e`。
  - 实测：旧判据出 1 个 62 / 出 4 个 13；新判据出 1 个 **0** / 出 4 个 **142**。
  - 教训：**「用户已经在看的东西不要动」这条理由只在收益小的时候成立**。这里收益是 62 个视频从「没法挑」变成「能挑」，远大于四个色号变化的成本。下一个人如果又想往回改，先去看 `tests/video-palette.test.ts` 的注释。

## 七、2026-11-17 增补：四件只有写下来才不会重犯的事

### 1. `Playfair Display` 是**用户机器上装的字体**，仓库里没有

项目**零字体文件、零 `@font-face`**，全部走系统字体名 + fallback。这本身是对的（不联网、不加包体积、无授权风险），但有一处依赖是隐式的：

`Playfair Display` 只装在用户本级字体目录（`%LOCALAPPDATA%\Microsoft\Windows\Fonts\PlayfairDisplay-VariableFont_wght.ttf` 与 `...-Italic-VariableFont_wght.ttf`），**换一台机器会静默回退到 Georgia**——不报错、不警告，只是封面上的 `DUMBRAVEN` 字形变了。共 9 处引用：`src/skin/collage-type.css:351,382`、`src/skin/collage.css:321,399,703`、`src/skin/stage.css:422`。

要么将来打进去（会加 3~4 MB 包体积，要先确认授权），要么接受「在新机器上字体会变」。**不要以为它在仓库里。**

### 2. 死代码审计的「没删清单」比「删了什么」更重要

2026-11-17 清了 12 条 TSX 零引用的 CSS 规则 + `mediaActions` + `inkSoft` 整条链路 + 两个颜色令牌（提交 `dc97df9`，asar 从 1418547 降到 1398886）。门禁全绿证明了删的东西一个都没在渲染里生效。

但下面这些**同样看着像死代码，实际不能删**：

| 看着像死代码 | 为什么留着 |
| --- | --- |
| `.transport` / `.channel-button` / `.cover-edition` / `.cover-bottom` / `.record-caption` / `.focus-hint` | `src/styles.css` 里有同名规则且可能有动态挂类，删了 `skin/` 那份等于放行原版样式，视觉会回退 |
| `.queue-item.drop-before::before` | 原版遗留的拖拽插入线，`AGENTS.md` 已记录它现在是死规则——但删它属于「改原版约定」的边缘，没有收益 |
| `defaultTracks` / `defaultMix` | 5 个测试文件拿它们当混音平衡与避让曲线的 fixture |
| `raven-logo.png`（`extraResources`） | `electron/main.cjs:19-22` 的 `appIcon()` 读 `process.resourcesPath` 根目录。为省 202KB 让图标改成读 asar 内 PNG，不值 |
| `src/styles.css` 里所有零引用规则 | 原版约定一字不改 |

审计子智能体给出的 8 条我逐条 grep 复核后才动手——**这个过程本身比结果重要**，它也会误报。

### 3. electron 的 14 个安全 advisory 判定「不可达」的依据

`npm audit` 报 8 条（1 high / 7 moderate）。high 那组是 electron 40.10.6 的 14 个 advisory，**全部与「加载外部页面」有关**（sandboxed iframe 绕过 allow-popups、OpenURLFromTab 丢沙箱继承、`<webview>` 在 Worker 里开 Node 集成、HID/USB/pointer-lock/openExternal 权限归错源、SameSite 不作用于链接开窗、extension `tabs.query` 泄露 URL、eMacro 中间证书）。

判定不可达的依据（都是可以重新验证的）：

- 三个窗口**全部 `loadFile()` 本地文件**：`electron/main.cjs:56` → `../dist/index.html`、`electron/desktop-stage.cjs:120` → `../dist/desktop.html`、`electron/focus-mini.cjs:102` → `mini.html`
- `grep -rn "loadURL\|webview\|iframe" src/ electron/ *.html` 除注释外零匹配
- `index.html` 的 CSP 是 `default-src 'self'`，无 CDN 引用
- 三处都已补 `setWindowOpenHandler(deny)` + `will-navigate` 拦截（提交 `3fac032`，原来只有主窗口有）

其余 7 条（`minimatch` / `fast-uri` / `@electron/universal` / `app-builder-lib` / `dmg-builder` / `electron-builder` / `electron-builder-squirrel-windows`）**全在 devDependencies**，只在打包机跑，不进产物。

所以**没有升级 electron**（40.10.6 → 41.x 跨大版本，为了走不到的路径冒渲染回归不值）。如果将来真的加了外部页面入口（在线封面、插件、任何 `loadURL`），这 14 条会**立刻全部变成可达**，那时候必须先升级再加功能。

### 4. 函数注释覆盖率从 44% 补到 63%，剩下的不该硬补

2026-11-17 给真正有逻辑的函数补了中文注释，覆盖率（同口径：正则找函数定义、往上找紧邻注释行）从 **44.3%（522 个 / 231 个有注释）到 63.4%（331 个）**。

补的时候有一条标准：**只补「为什么」，不补「是什么」**。所以这些没补：

- `const sync = () => ...`、`finish` / `done` / `cancel` 这类局部回调——它们的作用域只有十几行，读一遍上下文就懂了
- 一行的 getter / 纯委托（`get x() { return this.y }`）——补了只会稀释真正的注释

补的那批集中在**最容易改错的地方**（`src/audio.ts` / `src/player.ts` / `src/focus.ts` / `src/layers.ts` / `src/records.ts`），写的是变量之间看不见的耦合，比如：

- `src/player.ts` 的 `schedule()`——三条不变量（串行队列 `this.pending`、环境音不挡音乐但 `finally` 仍要 await、每步回来 `valid()` 复查）
- `src/audio.ts` 的 `detachLineIn()`——**不能动 `revision`**，否则正在解码的环境音一起被取消，表现为「接外部音乐后环境音再也不响」
- `src/layers.ts` 的 `settleAt()`——跨进程 round-trip 里桌面窗手上还是旧位置，会「先弹回原位再瞬移」
- `src/focus.ts` 的 `dayKey()`——不能用 `toISOString().slice(0,10)`，那是 UTC，东八区早上 8 点前会显示昨天
- `src/templates.ts` 的 `collageTone()`——三层明度阶梯固定不跟画面亮度走；`hint.sat` 与 `lead` 的区别不能省

**剩下的 207 个不补是有意的**，不要为了把数字刷到 100% 去写废话。

## 八、2026-11-18 增补：四条实测出来的判断

这一节全部来自 UI 审计（`ui-taste` 的 `audit` 入口）里的实测，不是读代码推出来的。共同点：**它们都会让下一个人做出错的决定**——要么删掉不该删的东西，要么把有意的设计当成 bug 改掉，要么相信一个永远会说谎的探针。

### 1. `tools/probe/contrast.cjs` 在这个项目里会稳定报 12 条假阳性

它量文本对比度的方法是「沿**祖先链**往上找第一个不透明背景」，而本项目的激活态黑胶囊**不是祖先**，是**兄弟元素**画的：

- `.nav-marker`（页签滑动指示条，`src/skin/shell.css:128`）
- `.flip-marker`（筛选滑块，`src/skin/shell.css:188`）
- `.template-marker`（模板滑块，`src/skin/atmosphere.css:472`）

三个都是绝对定位的兄弟节点，于是探针一路往上找到了页面底色 `#f0efea`，报「白字压在 `rgb(240,239,234)` 上 1.15:1」——而实际是白字压在黑胶囊上。

**不要因为这个去改颜色。** 正确的取证方式是截图后用像素量：`tools/probe/contrast-px.cjs`（收集 221 个自持文本节点的元素 + 截整页）+ `tools/probe/contrast-px.py`（PIL 取矩形内出现次数最多的颜色当底色，再算 WCAG）。跑完的结果是：21 条不达标里，底色可信（众数占比 ≥ 0.45）的只有 7 条，而那 7 条全部是 `.tpl-badge` 的前景取样错位 —— **净 0 条真缺陷**。

判据值得记住：**文字笔画是少数像素、背景是多数**，所以「矩形内众数」比「祖先链第一个不透明背景」可靠得多。

### 2. 票根徽章上那圈深棕描边是对比度的必需品，不是装饰

`.tpl-badge`（竖排 DUMBRAVEN 胶囊，`src/skin/collage.css:399` 一带）：

- 金色 `#d4a040` 压在胶囊那层半透明大理石蓝 `#6486b1` 上，只有 **1.59:1**
- 加上 `-webkit-text-stroke: 0.03em #2a2318` 之后，金 vs 深棕是 **6.58:1**

所以那圈描边**不能因为「看着像多余的装饰」删掉**。原注释里已经写了这句话，这一节补上实测数字，让它有据可查。

### 3. `.overlay` 的虚线焦点环与 `.dw` 的实线焦点环，**是有意两套，不是不一致**

- `.overlay`（普通图层块，`src/skin/atmosphere.css:63`）用 `::after` 画白色**虚线**——不占布局，位置是百分比定位的
- `.dw`（透明版式那几块字，`src/skin/stage.css:380`）用 `outline` 画白色**实线**——因为这批是 `text-shadow` + `-webkit-text-stroke` 画出来的字，外面再套 `box-shadow`/虚线会被描边压住

**真正的 bug 只有一处**：`.overlay` 是 `<div tabindex>`，而 `styles.css` 的焦点环规则只挂在 `button / a / input / select / textarea / summary` 上，浏览器于是按默认行为补了一圈 `outline: auto`（Chromium 下橙黄）。截图里能同时看到里圈橙黄实线 + 外圈白虚线两层。

修法是 `.overlay:focus-visible { outline: none }` —— **只关掉默认值，让作者原本设计的虚线成为唯一指示**。不要把两处改成一样。

### 4. 圆角：外壳与放映台对齐了，全屏仍然直角

同一个 App 里原来有两套圆角：外壳 `.cabinet` 26px / `.turntable` 28px，而窗口态的放映台 `.theater-screen` 只有 16px。2026-11-18 把窗口态提到 **26px**（`src/skin/theater-fix.css:30`），全屏那条 `border-radius: 0`（`src/skin/atmosphere.css:362`）保持不动——全屏时它不是卡片而是整块屏。

两档之间的实际差别量过：**488 / 1024000 像素（0.048%）**，全部落在四个角的抗锯齿边缘，画面内容没有被切掉（`tools/probe/theater-radius-ab.cjs` 用同一页同一位置 A/B 出图，`tools/probe/theater-radius.cjs` 量窗口态实际圆角——注意 `shell-radius.cjs` 用的是 `launch()` 默认的 `expand: true`，会把放映台点成全屏、于是恒量到 `0px`）。

**票根不动**（用户明确说过）。

## 九、2026-11-18 增补：两个子窗口的性质完全不同

主界面之外还有两个窗口，它们的样式来源不同，**能不能被三道门禁保护也完全不同**。搞混这一点会白干一整轮。

### 1. 桌面放映窗不是「另一套样式」

`desktop.html` + `src/desktop.tsx` 照样 `import './styles.css'` 和 `'./skin-bold.css'`，只在最后多一条 `./desktop.css`。也就是说它和主界面是**同一套视觉、同一份层叠顺序**，已经被样式快照与像素基线覆盖（`.qa/baseline` 里的 `wide/window-透明` 就是它）。

**结论：不需要为它单独审一遍，也不该给它写单独的视觉门禁。** 它唯一的特殊之处是 `data-chrome="hidden"` 且没有交互（用户点主界面「放到桌面」才出现）。

### 2. 番茄钟小窗是唯一不受门禁保护的样式

`electron/mini.html`（352 行）把整套 CSS **内联**在文件里，不加载 `skin-bold.css`。原因是它的 CSP 极严：`default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:`。

代价是：**它不在 `src/skin/` 体系内，也跑不到那两道门禁**（门禁只抓主窗口的 12 份快照 + 28 张像素图）。彩胶的渐变只能在这里重画一遍，于是就有了「两处实现靠人眼对齐」的隐患。

2026-11-18 逐条对出来的偏差，**三种性质完全不同，必须分开判断**：

| 工艺 | 盘内差异像素（共 1444） | 结论 |
|---|---|---|
| `swirl` | 161 / 11.1% | `mini.html` 只有 4 层渐变，`styles.css` 有 5 层（少了 `ellipse 40% 60% at 12% 72%`）→ 已补 |
| `splatter` | **5 / 0.35%** | 少 4 个颜料点，但都是 0.5~0.8px 的散点，肉眼无感 → **判定不值得改** |
| `halo` | **984 / 68.1%** | 原写成 `.pressing-glow, .pressing-halo { ... }` 共用一条渐变，两种工艺长得**完全一样** → 已拆开 |

**这条最重要**：`halo` 的修法是**只改渐变，不照抄主界面的外发光**。`styles.css` 里还有一条 `.pressing-halo .vinyl-label { box-shadow: 0 0 11px ... , 0 0 24px ... }`，那圈光晕是按主界面标签直径约 72px 调的（`.vinyl-label` 是盘的 36%），而 mini 的 `.disc::after` 只有 13px——照抄会让光晕半径比标签本身还大，把标签糊成一团亮斑。`tools/probe/mini-halo-variants.cjs` 做过对照：加 4px/9px 与照抄 11px/24px 两种方案都比不加更糊。

**所以「参数与主界面对齐」这句话有例外**：凡是尺寸相关的值（发光半径、投影、描边宽度），换到 306×96 的窗口里都得按比例缩，不能直接搬。

### 3. 怎么验这个不受门禁保护的文件

只能靠探针（都在 `tools/probe/`，已登记进 `tools/README.md`）：

- `mini-look.cjs` —— 八种状态（swirl/marble/splatter/glow/halo/break/long-break/light-disc）全部渲染 + 几何，顺带回读 `backgroundImage` 的分层数
- `mini-pressing-ab.cjs` —— 把主界面那几段 CSS 注入进去，与原位各拍一张逐像素比
- `mini-halo-variants.cjs` —— 变体对照，用来找「哪一档才不糊」
- `mini-contrast.cjs` —— 三阶段的文本元素 + 截图，配同一套「像素众数」算对比度

对比度实测（与主窗口同一口径）：主数字 `#ffffff` on `#101010` = **19.03:1**（需 3.0），副标题 `#8b8b85` = **5.55:1**（需 4.5），专注/休息/长休息三阶段完全一致（阶段只换环颜色 `#ffffff` / `#c7c0f0` / `#a8e6c1`，不换文字色）。

**动手改 mini.html 之后的验收清单**（没有门禁兜底，只能人工走）：`tsc` + `npm test` + `npm run build`（产物 hash 应**不变**，因为 src/ 没动）+ 跑上面四个探针 + `npm run package:win` 后 `npx asar list` 确认打进去的是改后版本。

## 十、三句话

1. **不要相信「看起来该改」的直觉，尤其当它叫“优化”的时候。** 这一轮唯一一次接近灾难的改动（`contain: paint`）就是一条教科书式的性能优化。
2. **凡是能 grep 验证的事，一律 grep。** 记忆会错，`AGENTS.md` 也会错——这一轮就修正了两条它写错的状态类说明。
3. **用户能看出动画的差别。** 切歌动画改过三轮，避让手感调过多轮，圆角从 `squircle` 换到 `superellipse(1.2)` 又微调过。不要用“差不多”交付视觉和手感；也不要在没确认方向时就把主观项（视觉、手感、节奏）改掉。
