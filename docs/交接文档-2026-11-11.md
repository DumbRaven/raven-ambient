## 2. 硬约束（违反会出事）

### 2.1 package.json 的 `name` 永远不要动

```json
"name": "raven-ambient-bold"
```

`userData` 由 `app.getName()` 决定，取 `name` **不是** `productName`。
改了数据目录会变，用户 17 张唱片的收藏会像全丢了。
显示名已经是「Raven Ambient」，**只有 `name` 这一个字段是有意保留的**。

### 2.2 原 `src/styles.css` 一字不改

所有新视觉写在 `src/skin-bold.css`。`main.tsx` 里 `styles.css` 先加载、
`skin-bold.css` 后加载——**同优先级后者赢**，所以要覆盖原规则得让它更具体（或写在后加载文件里）。

改覆盖层前先对照 `styles.css`：写 `background` / `transform` 简写会把原规则里的子属性一起重置。

### 2.3 拼贴版式外观不许改

用户 m11244 明确说过。拼贴的几何、字号、配色都是逐像素对齐参考图定下来的，
**任何塞进拼贴画面的东西都要走 `TemplateStage` 的 props**（只收数据、不收位置和开关），
不要接图层那套拖拽。拼贴也**不参与图层缩放**（传 `scalabe={false}`，永远按 1 倍渲染）。

### 2.4 改源码的方式

- 用 `write` / `edit` / `read`，或 Node 脚本。
- **绝不用 PowerShell 文本 cmdlet 改源码**（GBK 会毁 UTF-8 中文）。
- **`node -e` 里写含引号 / 反引号 / 中文的多行脚本必被 PowerShell 吃掉**
  （报 `SyntaxError: Expected unicode escape` 或 `Unexpected token`）。
  一律写成独立 `.cjs` 文件再跑；脚本里要嵌文档（全是反引号）改用**行数组 `.join('\n')`**。
- 整段替换前先 `count` 断言命中数（`expected 1 hit, got 2`），否则静默不动。
  **长的先换，换完短的才是唯一**（`1,376,284 字节` 这种串可能在 §4 与 §9.23 各出现一次）。

### 2.5 提交

消息先 `write` 到 `F:\Vibe-bold\.git\COMMIT_MSG_TMP.txt`，再 `git commit -F`，
提交完删掉。**PowerShell 里 `git commit -F - <<'EOF'` heredoc 会被解析器拒绝。**

### 4.2 视觉规格（量出来的，不是猜的）

一张票整体 **1124×563 ≈ 2:1**，其中画面占 **69.22%**、票根占 **30.6%**，撕线在 x=870。

> `panel.x` 就恒等 700）；② 判别式必须互斥（票根深色字会被「深色=照片」命中）；
> ③ 单像素命中不算数（红字饱和度高，逐像素「或」会让照片右界吃到 x=1000）→ 改逐列投票；

### 4.3 一张票是「两块纸」，不是一整块

参考图上照片块与票根块**各自成形、中间留一道 3px 缝**露出页面底色，撕线就在缝里。
做成一整块的话，齿孔无论怎么挖都只是「一张纸上的花纹」——这是第一版做错的地方。

- **照片块** `.ticket-shot`：**上下直边**，只有左右两排内凹齿孔。两层径向遮罩 + `mask-composite: intersect`。
  画面 `aspect-ratio: 16/9` 且 `object-fit: contain`（用户要「展示全了」，裁掉不算）。
- **票根块** `.ticket-panel`：右缘是**向外鼓**的半圆（波浪），
  「一层矩形 ∪ 一列圆心压在右边界上的圆」，`mask-composite: add`。
- 三个坑：
  1. **`box-shadow` 会被 mask 一起裁掉** → 两块都改 `filter: drop-shadow(...)`；当前张改 `inset` 内描边。
  2. **令牌必须扩到浮层**（`.ticket, .ticket-lift, .ticket-panel, .ticket-lift-panel`）。
     只写在 `.ticket` 上时，浮层不是它的后代 → 变量解析失败**静默退回透明**，整张票是灰的。
  3. **浮层齿要大一圈**（`--edge-radius: 5px / --edge-step: 20px`），放大后还用小齿像一圈灰点。

### 4.4 四种版式，按文件散列

```ts
export type TicketLayout = 'classic' | 'arc' | 'stack' | 'editorial';
export function ticketLayout(id: string): TicketLayout   // ticketHash(id) % 4
```

| 版式 | 参考 | 骨架 |
|---|---|---|
| `classic` | ref-1 / ref-2 | 标记、ADMIT ONE、片名、两组两栏字段、票号、条码 |
| `arc` | ref-3 / ref-4 | 居中标题、`★ ADMIT ONE ★`、带竖分隔的两栏、方框座位 |
| `stack` | ref-5 | 纵排「标签在上、值在下」三组，红色大字票号 |
| `editorial` | ref-6 | 顶部小字、大号两行片名（不大写）、细字说明、条码下影院名 |

**「看起来随机」不是「真随机」**：同一个文件每次重渲染必须同款，否则翻页回来票面变样，
一眼就假。所以照旧走 id 散列（`ticketHash`，FNV-1a）。

`ticketStamp(id)` 提供四版共用的字：日期（4~12 月 / 1~12 日，**保证任何月份都合法**）、
时刻、座位、行、影院名、细字。**票面上的每一格都必须是真的**——第一版印过
`TIME: 1 KB`（文件大小）和 `DATE: 01 / 04`（列数常量），两个都不该出现在票上。

### 4.5 纸纹

`src/paper.ts` 生成 `feTurbulence type="fractalNoise" baseFrequency="0.9" numOctaves="3" seed="17"`，
然后两步压对比才像纸：

1. `feColorMatrix saturate 0` **先合成灰度**——三个通道各自独立，不先合成会得到彩色噪点；
2. `feComponentTransfer` 每通道 `slope="0.34" intercept="0.83"` 压到 0.5 附近一小段，
   再 `feBlend mode="multiply"` 乘到纸色上。直接乘原噪声是满幅黑白噪点。

`<feFuncA type="linear" slope="0" intercept="1"/>` **必须钉死 alpha**，否则整块纸半透明。

宿主由 `MediaTickets` 挂在 `<body>` 上，**不能放票根里**——被 `mask` / `overflow` 裁的容器里
Chromium 判滤镜失效、静默退回 `none`，没有任何报错。

## 5. 图层（叠加元素 + 桌面组件）

`src/layers.ts`（数据）+ `src/LayerStack.tsx`（唯一渲染层）+ `src/TheaterLayers.tsx`（菜单）。

- 一共六种：`clock` / `date` / `title` / `timer` / `disc` / `now`。
- **数据里没有 `on` 字段**——「在列表里就是显示，不在就是没加」。两处各存一份只会对不上。
- 旧存档从 `raven-overlays` 与 `raven-desktop-widgets` 搬家，**叠加元素那份优先**，空数组是合法状态。

  只做前半句不够：不给手柄却让它跟着照片版式一起变大，用户看到的是「我没动它，它自己变了」。

## 6. 探针与验证（这一节最容易浪费时间）

### 6.1 怎么跑

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
$p = Start-Process -FilePath 'node_modules\electron\dist\electron.exe' `
  -ArgumentList 'tools\probe\xxx.cjs','--no-sandbox' -NoNewWindow `
  -RedirectStandardOutput '.tools\out.txt' -RedirectStandardError '.tools\err.txt' -PassThru
[void]$p.WaitForExit(180000)
Get-Content .tools\out.txt | Select-Object -Last 5
```

- **`ELECTRON_RUN_AS_NODE` 在 shell 里是常驻的**，不清掉会以纯 Node 模式启动，
  报 `Cannot read properties of undefined (reading 'setPath')`。
- **直接管道 `| Select-Object -Last N` 会缓冲住全部输出**，看起来像卡死。
- `harness.cjs` 的 `report()` 内部会 `app.exit(0)`，所以探针必须用 `guard(async () => {…})` 包裹；
  否则报 `PROBE_FAIL Session can only be received when app is ready` 并卡住。
- `harness.cjs` 加载的是 `dist/index.html`，**改完源码必须先 `npm run build`**。

### 6.3 探针踩过的坑（每一条都吃过）

- **列表类探针必须 `expand: false`**。全屏时 `.ticket-grid` 是 `display:none`，
  所有 `getBoundingClientRect()` 都是 0，量出来一堆假值（`columns:3 / rows:1 / tearing:false`）。
- **截图与坐标必须一次成对**：用 `win.webContents.capturePage({ x, y, width, height })` 直接吃页面坐标，
  别再「滚动 → 量矩形 → 截图 → 裁」——中间位置会变，截出来整体偏一段。
- **一次只滚一张**：先滚一圈把所有坐标收下来再逐张截，页面会停在最后一次滚动的位置，
  后面几张截到的全是同一张（表现为「四种版式只截出两款」）。
- **`reload()` 之后应用回到唱片柜页**，媒体那层是 `display:none`，量什么都是 0×0。必须重新点导航。
- **摘图层不能靠点菜单**：摘一颗 React 重渲染，手上那串按钮引用立刻变成游离节点。
- **拖动必须按帧派发**：`pointerdown` → `wait(260)` → `pointermove` + `pointerup`；
  同一 tick 里连发会因为 `useEffect` 还没挂监听而整段丢掉。
- **`sendInputEvent({type:'mouseDown'})` 产生不了 `pointerdown`**，要在页面内
  `dispatchEvent(new PointerEvent(...))`；反过来 `:hover` 只能用 `sendInputEvent({type:'mouseMove'})` 触发。
- **Escape 关浮层**：监听挂在 `window` 上，`document.dispatchEvent` 不冒泡，必须 `window.dispatchEvent`。
- `launch()` 的 `close()` 是 `app.exit(0)`，**一个探针起不了两个窗口**，要量两种状态就用同一个窗口来回切。
