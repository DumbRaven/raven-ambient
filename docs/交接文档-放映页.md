## 5. 放映页整体架构

### 5.1 数据流

```
用户点「从本地添加」或「读取壁纸库」
   ↓
页面把动作写进 window.__ravenMediaOutbox
   ↓
主进程每 400ms 轮询取走（无 IPC，因为 sandbox:true 无 preload）
   ↓
主进程 dialog.showOpenDialog / 扫描目录
   ↓
主进程 executeJavaScript 调 window.__ravenMedia(bridge 推消息)
   ↓
页面 listenMedia 收到，写进 cabinet.media（只存绝对路径，不复制文件）
   ↓
页面渲染 <img src="media://local/%E7%BB%9D%E5%AF%B9%E8%B7%AF%E5%BE%84">
   ↓
主进程 protocol.handle('media', ...) 校验白名单 → net.fetch(pathToFileURL)
```

**为什么不用 IPC**：页面是 `sandbox: true` + `nodeIntegration: false` + 无 preload，加 preload 要改主进程配置。这套「outbox + 轮询」是项目里已有的成熟模式（`now-playing.cjs` 就是这么做的），照抄的。

### 5.2 `media://` 协议

```js
// 必须在 app.ready 之前
protocol.registerSchemesAsPrivileged([{
  scheme: 'media',
  privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true, corsEnabled: true },
}]);

// app.ready 之后
protocol.handle('media', (request) => {
  const target = decodeURIComponent(new URL(request.url).pathname.replace(/^\/+/, ''));
  if (!insideAllowed(target)) return new Response('', { status: 403 });
  return net.fetch(pathToFileURL(target).toString());
});
```

- URL 编码一对：`media://local/${encodeURIComponent(绝对路径)}` ↔ `decodeURIComponent(url.pathname)`。中文/空格/`&`/`#` 全部实测正确。
- 白名单用 `path.relative(base, target)` 判 `rel && !rel.startsWith('..') && !path.isAbsolute(rel)`。
- `net.fetch` 会处理 Range 请求和流式读取，视频可以拖进度。

### 5.3 白名单的两层

```js
const allowed = new Set();      // 目录
const looseFiles = new Set();   // 单独挑进来的文件
```

**为什么要分两层**：用户「选几张文件」时不该把整个素材盘放进来，也不该在来源列表里冒出没选过的文件夹。

重启后白名单是空的（只在内存里），所以：
- `Cabinet.mediaDirs` 持久化目录列表
- 单文件靠 `looseMedia(items, dirs)` 从条目里反推（不在任何目录里的就是单文件）
- 启动时 `restoreMediaDirs(dirs, files)` 重新登记

## 6. 三套版式

```ts
// src/templates.ts
export type TemplateId = 'collage' | 'photo' | 'frame';
```

| id | 名字 | 说明 |
|---|---|---|
| `collage` | 拼贴 | **用户视频里那套**，重点在这儿 |
| `photo` | 照片 | 整张铺满，手写体标题压左上，曲目列在右侧 |
| `frame` | 画框 | 画面缩成一枚卡片，四边留底色，底部一行小字 |

版式选择存 `localStorage['raven-stage-template']`（看片偏好不该触发写盘）。

### 配色算法（`collageTone`）

三块颜色**是同色系明度阶梯**，不是三个独立取色：

- 底色 `l = 0.14`（最暗）
- 面板 `l = 0.55`（中间）
- 信息条 `l = 0.88`（最亮）
- 色相几乎相同

**主色相怎么算**：饱和平方加权圆周平均，但——

```ts
const coherence = Math.hypot(x, y) / total;
if (coherence >= 0.5) {
  hue = 圆周平均
} else {
  hue = best * 30 + 15;   // 退化成 30° 分桶取票数最高的桶
}
```

**为什么要判 `coherence`**：金→蓝渐变的两个色相差 160°，圆周平均会落在正中间的绿色上——**画面里根本没有绿色**，整个版式就染成了一种不存在的颜色。这是实测踩出来的。

`ToneHint = { hue?, base?, panel?, bar? }` 可以逐档覆盖：
- `custom` 模式：用户直接给三档颜色
- `pick` 模式：把画面第 N 个主色转成 hue，明度仍自动排
- `auto`：全自动

### 7.4 面板的形状（**这一条最容易被误解**）

绝对坐标：`(1271,34) (1886,34) (1886,630) (1582,414) (1271,636)`

> 「不是面板被切，而是面板本身绘制的时候就是一个不规则的图形」（m613088）

所以**不要在面板上挖一个圆洞**——面板本身就是这个五边形。我在这上面走了三轮弯路：

1. 按「矩形挖半圆」做 `clip-path` → 用户说不对
2. 按 AE shape 图层高度（55.74%，底边 y=636）做 → 挖出来的洞极大，面板只剩左右两条细边
3. 把面板高度贴到画布底部（96%）→ 圆根本不切底边，挖洞失效退化成矩形

### 7.5 三块外形：用 SVG mask，不要用 clip-path

```css
/* 画面块 1210×708，左上角大弧半径 162px */
.template-collage > .tpl-block-media {
  border-radius: 0;
  mask-image: url("data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 1210 708' preserveAspectRatio='none'><path d='M162,0 L1210,0 L1210,708 L0,708 L0,162 Q0,0 162,0 Z' fill='white'/></svg>");
  mask-size: 100% 100%;
  mask-repeat: no-repeat;
}

/* 信息条 1210×274，右下角顺着唱片圆内凹 */
.template-collage > .tpl-block-bar {
  clip-path: none;
  mask-image: url("data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 1210 274' preserveAspectRatio='none'><path d='M1210,4 L1210,0 L0,0 L0,274 L1072,274 Q1120,232 1210,127 L1210,4 Z' fill='white'/></svg>");
  mask-size: 100% 100%;
  mask-repeat: no-repeat;
}
```

**为什么必须用 mask 不用 clip-path**：

- `clip-path: path()` 的坐标是**像素**，不随容器缩放。窗口一大一小，弧就变形。
- `mask-image` 配 `preserveAspectRatio="none"` 可以按块宽高等比拉伸。
- `mask-composite: exclude` **在这版 Chromium 上会把整块面板连同文字一起抹掉**（元素在、位置也对，一个像素都不显示）。我试过，放弃了。

## 8. 叠加元素与雨层

### 8.1 叠加元素（`src/overlays.ts` + `src/OverlayLayer.tsx`）

```ts
export type OverlayId = 'clock' | 'title' | 'date' | 'timer';
export type OverlaySpot = { x: number; y: number };  // 0–1 比例，不是像素
```

- 位置存**比例**而不是像素，换窗口大小位置才不会跑。
- 拖动：`setPointerCapture` + 拖动过程中存本地 state，**松手才写回 localStorage**（每帧写会卡）。
- 番茄钟数据来自 `readFocus()`（`src/focus-bridge.ts`）——**不自己起计时器**，两处各算各的，暂停一次就对不上。
- 存 `localStorage['raven-overlays']`。

### 8.2 雨层（`src/rain.ts` + `src/RainLayer.tsx`）

```ts
export type RainMode = 'slide' | 'streak' | 'both';
export type RainSetting = { on: boolean; mode: RainMode; strength: number; opacity: number };
```

**参数照 AE 的 CC Mr. Mercury**：

## 9. 已验证的技术事实（不要再验一遍）

这些都是花了很多轮实测出来的，直接信：

### 9.1 布局

- **`cqh` 会把字号压没**。每块各自是 `container-type: size` 容器，信息条只有 274px 高 → `1cqh = 2.74px`，字号被压成 4px 看不见。**一律用 `cqw`**（容器宽度 1%）。
- **容器查询必须是「每块各自是容器」**：`.template-collage > .tpl-block { container-type: size }`。只给外层设的话，`cqw` 会按整块画布算，220px 宽的面板里 `6.6cqw` 变成 45px，把面板撑爆。
- **台面锁 16:9**：`.media-room .media-theater .theater-screen { width: 100%; aspect-ratio: 16/9; max-height: min(70vh, calc(100vw * 9 / 16)); }`。只写 `aspect-ratio` 时宽度是 auto，浏览器会拿高度上限倒推宽度。

### 9.2 层叠

- **CSS 同名规则叠加是这个项目最大的坑**。`.tpl-words` 曾经有 7 条、`.tpl-brand` 5 条、`.tpl-block-panel` 8 条。早先那几版里的 `position: absolute` **一直在生效**，后来写的 `grid-row` 改不动它，所以看起来「怎么调都不对」。
- **改版式前先数一遍同名规则有几处**：
  ```bash
  node -e "const s=require('fs').readFileSync('src/skin-bold.css','utf8'); let n=0,a=-1; while((a=s.indexOf('.tpl-words {',a+1))>=0)n++; console.log(n)"
  ```
- 去重脚本按「选择器 + 花括号配对」整块删，会**切断带逗号的多选择器和 `@media` 块**（CSS 报 `Unexpected "@media"`）。要么先做括号配对校验，要么用**行号**精确替换。

### 9.3 SVG filter

- `<svg width="0" height="0">` 里的 filter 会被 Chromium 判失效 → 改成 `width="1" height="1"`。
- filter 原语里放 SMIL `<animate>` 会让整个 filter 判失效。
- **必须用内联 `style={{ filter: 'url(#id)' }}`**——样式表里写 `filter: url()` **不命中**，`document.styleSheets` 遍历也查不到这条规则。
- filter 元素挂到 `body` 上，不要放在被 `clip-path` / `overflow` 裁的容器里。

### 9.4 媒体

- **`<video preload="metadata">` 不解第一帧**，必须显式 `video.currentTime = 0.1` 才画出画面。
- **浏览器对 403 的媒体地址不会重试**。白名单变化后必须重新渲染元素（用 `mediaReady` 门控），否则格子永久空着。
- 178 个 `<video>` 同时挂会拖死窗口 → `IntersectionObserver`（`rootMargin: '280px 0px'`）+ `seen: Set`。
- **`media://` 的图画进 canvas 会跨域**，`getImageData` 抛 SecurityError（异常被 `catch` 吞掉后返回空数组，上层就退到兜底色）。修法：`image.crossOrigin = 'anonymous'`。
- 扫描排序必须 `localeCompare('zh-CN', { numeric: true })`，`readdir` 顺序由文件系统决定、不稳定。
- 重扫要用 `replaceMediaDir`（先清空该目录再填）。`mergeMedia` 只增不减，用户在资源管理器删掉的文件会一直留着、点开 404。

### 9.5 视频取色

`src/video-palette.ts` 里**必须 seek 到 `duration * 0.12`** 再抽帧。很多视频开头是黑场或台标，停在 0 秒取出来一片黑，等于没取。

### 9.6 全屏

- 真全屏要主进程 `win.setFullScreen(true)`，页面 `position: fixed` 只盖得住内容区，任务栏和窗口边框还在。
- **右侧那道白线的根因是滚动条**：内容高 1134 > 视口 1080，顶出 4px 滚动条，而 `position: fixed` 的定位基准不含滚动条，所以 `inset: 0` 只铺到 1916。修法：
  ```css
  html:has(.media-room.is-expanded),
  body:has(.media-room.is-expanded) { overflow: hidden; }
  ```

### 9.7 探针（验证脚本）

- **探针页面必须用真实的 `dist/index.html`**。自建 `file://` 页会让 `media://` 的视频报 `error 4`，误导判断。
- **探针必须在主进程先 `allowDir` / `allowFile` 再 `loadFile`**。页面发 `restore` 走 400ms 轮询，比图片请求晚；浏览器拿到 403 就不重试了。
- 探针灌 localStorage 后必须 `win.webContents.reload()` 再等 3 秒。
- 素材放 `%TEMP%` 会被系统清掉，**每次运行都要重建**，否则取色退回兜底色，截图看着像「取色算法错了」。

### 9.8 测量本身会骗人（这一轮踩了五个坑）

**「看着对不对」不算数，「量出来对不对」也可能被脚本 bug 骗。** 定值前先确认你在量的是同一块区域。

1. **截图分辨率会变，任何脚本都不许把宽高写死。** 同一个探针在不同 DPR / 显示器 / 窗口尺寸下截出的 PNG 尺寸不同（见过 3840×2160 和 1920×1080 两种）。写死宽高当 stride 用，读到不匹配的图时**不会报错**，只会行错位、`crop` 的 x 被 ffmpeg 钳到右下角，**输出看似正常的假值**。一律用 `tools/measure/pixels.cjs` 的 `load()`（内部走 ffprobe）。

2. **`cqw` 的基准跟着元素走，不是固定的。** 实测全屏 1920×1080 下：
   ```
   .template-collage   上 1cqw = 19.2px  （画布宽的 1%）
   .tpl-block-panel    上 1cqw = 5.55px  （面板宽 615 的 1%）
   .tpl-tag            上 1cqw = 5.55px  （它没有 container-type，继承面板的）
   ```
   所以同一个 `3.0cqw` 写在面板里是 16.6px、写在画布级元素上是 57.6px，**差 3.5 倍**。标题字号改错过一次就是这个原因。

3. **弧顶是 y 最小，不是 y 最大。** 面板弧向上鼓，用「y 最大」取到的是面板左下角。踩过一次，拟合出 `R=182` 全错（正确值 321.1）。

4. **按颜色逐列扫面板底边会被唱片照片污染。** 唱片里有与面板色相近的像素，采样点会掉进去，拟合出 `R=242`。**必须用连通域掩码**（`flood()` 返回的 `mask`）逐列取最低行，不能只返 bbox。

5. **拟合窗口不能太窄。** 面板宽的 0.62 倍拟出 `R=242`，0.75 倍拟出 `R=321.1`（正确）。Kasa 法在短弧上病态。

6. **文字带扫描窗口别撞进徽标胶囊。** 徽标的金色字母在亮度阈值下会被当文字。早期 `words-band` 模式用 `x 66.5..90%`，被污染成一个假的「8.40% 墨高」合并带。窗口右边界收到 **85%** 才对。

7. **胶囊宽度用颜色找不可靠，试了三次全失败。**
   - 「低饱和 + `r>95`」→ 量出宽 34%（整块面板都算进来）
   - 「连续 ≥70px」→ 19%（倒影层低对比渐变被算进来）
   - 限定窗口到 x86..99% → 10.07%（准值 7.30%，面板外 JPEG 噪点也是低饱和亮色）

   **结论：胶囊准值只读 DOM**（`tools/probe/geo.cjs` 的 `tag` 项），像素侧只用 `gold.cjs` 的 `STAR_BBOX` 当上界交叉验证。

8. **`goldBands()` 之类返回的是裁切图内坐标，不是原图坐标。** 打印时必须加裁切偏移。曾把它当绝对坐标传进去，两版结果不一致、白查一轮。

### 9.9 两色乌鸦：路径是怎么描出来的

原始 logo `docs/images/00-logo.png` 本身就是两色的（实测直方图：`rgb(33,42,50)` 占 2.73% 是身体、`rgb(93,108,120)` 占 1.09% 是翅膀亮区，其余 72% 是透明区，其 RGB 也是 0,0,0）。`ravenPath` 当年只描了 alpha 通道的整体剪影，所以填不出两色。

- `src/raven.ts` 的 `ravenWingPath`：标出亮色像素（`a>200 && r>60 && r<140 && b>70`）→ 全画布 4 邻域取最大连通域 → 逐行取左右边界 → 每 **5 行**一个点，先右边界向下、再左边界向上闭合。（每 12 行一个点时边缘是锯齿状。）
- **坐标映射是 `viewX = 25 + (px - 51) / 2`**：原图 1332×1204，alpha 包围盒 `[51,50]-[1284,1156]` 正好是 `ravenBox`（原点在 25,25、617×553）的两倍。**漏掉 `+25` 会让整块翅膀向左上错位、盖到鸟脖子上。**
- 着色：身体 `var(--tpl-panel)`、翅膀 `color-mix(in srgb, var(--tpl-bar) 65%, var(--tpl-panel))`。**不能直接用 `var(--tpl-bar)`**——那正是乌鸦脚下的底色，翅膀会和背景糊成一个洞。

| WGC（Windows Graphics Capture） | `CreateForWindow(Progman)` 建项成功，但 `IDXGISurface::Map` 返 `E_INVALIDARG`，建 staging 纹理在 .NET Framework 4 上反复崩 |

**当前状态**：功能整体删除，`scanWallpaper` 遇到非 video/image 的作品整件 `continue` 跳过。

### 10.2 其他不要重走的

- **`mask-composite: exclude`** 在这版 Chromium 上会把整块面板连同文字一起抹掉。
- **`clip-path: path()`** 只吃像素、不随容器缩放。
- **按「暗像素」找唱片**：会把壁纸背景算进去，量出假圆心。**判色分类（通道差）比明暗可靠**。
- **两处 `@media (max-width: 760px)` 把拼贴压成单列**：正式 exe 窗口 `innerWidth` 只有 666，这两条会让右列两轨变成 0px，**面板和唱片根本不渲染**。这个 bug 卡了三四轮。决策：版式固定比例，窗口小就整体等比缩小，**不改结构**。

### 12.3 这个环境特有的坑

- **`ops_bash` 里不能直接写 PowerShell 语法**（`Get-Process` 报 `command not found`）。要么写成 `.ps1` 再 `pwsh -File`，要么用 bash 语法。**探针现在不需要 ps1 了**，直接用上面的 `env -u` 一行式。
- **`pwsh` 内联 `node -e` 里写 `\"` 或中文常量必报 `Invalid string escape`**，一律写 `.cjs` 再 `node`。
- **`write` 工具对未读过的源文件报 `file has not been read`** → 先 `ops_read_files` 再写。
- **`edit` 对刚被 Node 脚本改过的文件报 `file changed since it was read`** → 重新读一次再 edit。
- **模板字符串（反引号包裹的）里不能再出现反引号**，即使是在注释里。会把字符串提前截断，报 `SyntaxError: missing ) after argument list`。定位方法：`node --check <file>`。
- **`ops_read_files` 显示路径时会转义反斜杠**（`F:\\Vibe-bold`），但文件里实际是单个 `\`。`edit` 的 `old_string` 要用单反斜杠，或者干脆用 Node 脚本按行号替换。

## 13. 协作教训（**这一节可能是最有用的**）

上一个对话在沟通上卡住了。我复盘出来的几条，希望你能避开：

### 13.1 「按 AE」= 一个像素都不许自己发明

我犯的最大的错：把 AE 里那个**不规则五边形面板**理解成「矩形挖了个圆」。他连着说了三次：

1. 「应该有尖角包住唱片」
2. 「不是嵌在面板里，那个面板本身就不是一个规则的形状」
3. 「而且不是面板被切，而是面板本身绘制的时候就是一个不规则的图形」

**如果他说「按 XX 来」，就去拿 XX 的原始数据，不要从截图反推。** 截图会有压缩、缩放、颜色偏差；而且我会把「视觉上像」当成「几何上对」。

这次真正的转折点是他让我导出 AE 数据，在那之前我一直在用「估算 + 截图对比」，每一轮都是错的方向。

### 13.2 每次改版式之前先数同名规则

这个坑我踩了至少五轮。`.tpl-words` 有 7 条同名规则，最后生效的是文件末尾那条，但中间那些 `position: absolute` 还在生效，所以「改了没反应」。

**改之前先跑一遍计数，改完再跑一遍确认只留一条。**

### 13.3 不要用「截图看着对」当验证

截图有延迟（`capturePage` 在图片解码后立刻拍会拿到还没上屏的那一帧），而且隐藏窗口不跑 rAF。**要量几何就用 `getBoundingClientRect()`，要验颜色就读像素**，别用肉眼。

### 13.4 他说「先别做了，告诉我你需要什么」

这句是信号：**他不是在催，是真的不知道该给什么了**。这时候正确的反应是立刻说清「我需要 X，因为 Y」，而不是继续试。

那次我问出来的是「AE 里能不能跑个脚本」，然后一切都通了。

### 13.5 他要的是「一起看」，不是「等指令」

他的原话：

> 「你要做的不是听我的指导，而是更频繁的告诉我你打算怎么做，为什么这么做而已」

但反过来也成立——**改了十几轮还没对，说明我在猜，而不是在看**。

### 13.6 一个具体的建议

如果你接着做版式，**第一件事应该是**：

1. 打开打包好的 exe
2. 切到放映页，加几张图
3. 截图
4. 和他的参考图并排放

如果差得远，**先把 AE 数据重新导一遍**（第 7.1 节），确认 `raven-shapes.json` 里的数字和现在 CSS 里的一致。别从我的中间结论出发。
