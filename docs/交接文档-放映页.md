## 5. 放映页整体架构

### 5.1 数据流

```
用户点「从本地添加」或「读取壁纸库」
   ↓
页面把动作写进 window.__ravenMediaOutbox
   ↓
主进程每 400ms 轮询取走（无 IPC，因为 sandbox:true 无 preload）
   ↓
主进程 dialog.showOpenDialog / 扫描目录
   ↓
主进程 executeJavaScript 调 window.__ravenMedia(bridge 推消息)
   ↓
页面 listenMedia 收到，写进 cabinet.media（只存绝对路径，不复制文件）
   ↓
页面渲染 <img src="media://local/%E7%BB%9D%E5%AF%B9%E8%B7%AF%E5%BE%84">
   ↓
主进程 protocol.handle('media', ...) 校验白名单 → net.fetch(pathToFileURL)
```

**为什么不用 IPC**：页面是 `sandbox: true` + `nodeIntegration: false` + 无 preload，加 preload 要改主进程配置。这套「outbox + 轮询」是项目里已有的成熟模式（`now-playing.cjs` 就是这么做的），照抄的。

### 5.2 `media://` 协议

```js
// 必须在 app.ready 之前
protocol.registerSchemesAsPrivileged([{
  scheme: 'media',
  privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true, corsEnabled: true },
}]);

// app.ready 之后
protocol.handle('media', (request) => {
  const target = decodeURIComponent(new URL(request.url).pathname.replace(/^\/+/, ''));
  if (!insideAllowed(target)) return new Response('', { status: 403 });
  return net.fetch(pathToFileURL(target).toString());
});
```

- URL 编码一对：`media://local/${encodeURIComponent(绝对路径)}` ↔ `decodeURIComponent(url.pathname)`。中文/空格/`&`/`#` 全部实测正确。
- 白名单用 `path.relative(base, target)` 判 `rel && !rel.startsWith('..') && !path.isAbsolute(rel)`。
- `net.fetch` 会处理 Range 请求和流式读取，视频可以拖进度。

### 5.3 白名单的两层

```js
const allowed = new Set();      // 目录
const looseFiles = new Set();   // 单独挑进来的文件
```

**为什么要分两层**：用户「选几张文件」时不该把整个素材盘放进来，也不该在来源列表里冒出没选过的文件夹。

重启后白名单是空的（只在内存里），所以：
- `Cabinet.mediaDirs` 持久化目录列表
- 单文件靠 `looseMedia(items, dirs)` 从条目里反推（不在任何目录里的就是单文件）
- 启动时 `restoreMediaDirs(dirs, files)` 重新登记

## 6. 三套版式

```ts
// src/templates.ts
export type TemplateId = 'collage' | 'photo' | 'frame';
```

| id | 名字 | 说明 |
|---|---|---|
| `collage` | 拼贴 | **用户视频里那套**，重点在这儿 |
| `photo` | 照片 | 整张铺满，手写体标题压左上，曲目列在右侧 |
| `frame` | 画框 | 画面缩成一枚卡片，四边留底色，底部一行小字 |

版式选择存 `localStorage['raven-stage-template']`（看片偏好不该触发写盘）。

### 配色算法（`collageTone`）

三块颜色**是同色系明度阶梯**，不是三个独立取色：

- 底色 `l = 0.14`（最暗）
- 面板 `l = 0.55`（中间）
- 信息条 `l = 0.88`（最亮）
- 色相几乎相同

**主色相怎么算**：饱和平方加权圆周平均，但——

```ts
const coherence = Math.hypot(x, y) / total;
if (coherence >= 0.5) {
  hue = 圆周平均
} else {
  hue = best * 30 + 15;   // 退化成 30° 分桶取票数最高的桶
}
```

**为什么要判 `coherence`**：金→蓝渐变的两个色相差 160°，圆周平均会落在正中间的绿色上——**画面里根本没有绿色**，整个版式就染成了一种不存在的颜色。这是实测踩出来的。

`ToneHint = { hue?, base?, panel?, bar? }` 可以逐档覆盖：
- `custom` 模式：用户直接给三档颜色
- `pick` 模式：把画面第 N 个主色转成 hue，明度仍自动排
- `auto`：全自动

绝对坐标：`(1271,34) (1886,34) (1886,630) (1582,414) (1271,636)`

用户原话：

> 「不是面板被切，而是面板本身绘制的时候就是一个不规则的图形」（m613088）

所以**不要在面板上挖一个圆洞**——面板本身就是这个五边形。我在这上面走了三轮弯路：

1. 按「矩形挖半圆」做 `clip-path` → 用户说不对
2. 按 AE shape 图层高度（55.74%，底边 y=636）做 → 挖出来的洞极大，面板只剩左右两条细边
3. 把面板高度贴到画布底部（96%）→ 圆根本不切底边，挖洞失效退化成矩形

### 7.5 三块外形：用 SVG mask，不要用 clip-path

```css
/* 画面块 1210×708，左上角大弧半径 162px */
.template-collage > .tpl-block-media {
  border-radius: 0;
  mask-image: url("data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 1210 708' preserveAspectRatio='none'><path d='M162,0 L1210,0 L1210,708 L0,708 L0,162 Q0,0 162,0 Z' fill='white'/></svg>");
  mask-size: 100% 100%;
  mask-repeat: no-repeat;
}

/* 信息条 1210×274，右下角顺着唱片圆内凹 */
.template-collage > .tpl-block-bar {
  clip-path: none;
  mask-image: url("data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 1210 274' preserveAspectRatio='none'><path d='M1210,4 L1210,0 L0,0 L0,274 L1072,274 Q1120,232 1210,127 L1210,4 Z' fill='white'/></svg>");
  mask-size: 100% 100%;
  mask-repeat: no-repeat;
}
```

**为什么必须用 mask 不用 clip-path**：

- `clip-path: path()` 的坐标是**像素**，不随容器缩放。窗口一大一小，弧就变形。
- `mask-image` 配 `preserveAspectRatio="none"` 可以按块宽高等比拉伸。
- `mask-composite: exclude` **在这版 Chromium 上会把整块面板连同文字一起抹掉**（元素在、位置也对，一个像素都不显示）。我试过，放弃了。

## 8. 叠加元素与雨层

### 8.1 叠加元素（`src/overlays.ts` + `src/OverlayLayer.tsx`）

```ts
export type OverlayId = 'clock' | 'title' | 'date' | 'timer';
```

**参数照 AE 的 CC Mr. Mercury**：

## 9. 已验证的技术事实（不要再验一遍）

这些都是花了很多轮实测出来的，直接信：

### 9.1 布局

- **`cqh` 会把字号压没**。每块各自是 `container-type: size` 容器，信息条只有 274px 高 → `1cqh = 2.74px`，字号被压成 4px 看不见。**一律用 `cqw`**（容器宽度 1%）。
- **容器查询必须是「每块各自是容器」**：`.template-collage > .tpl-block { container-type: size }`。只给外层设的话，`cqw` 会按整块画布算，220px 宽的面板里 `6.6cqw` 变成 45px，把面板撑爆。
- **台面锁 16:9**：`.media-room .media-theater .theater-screen { width: 100%; aspect-ratio: 16/9; max-height: min(70vh, calc(100vw * 9 / 16)); }`。只写 `aspect-ratio` 时宽度是 auto，浏览器会拿高度上限倒推宽度。

### 9.2 层叠

- **CSS 同名规则叠加是这个项目最大的坑**。`.tpl-words` 曾经有 7 条、`.tpl-brand` 5 条、`.tpl-block-panel` 8 条。早先那几版里的 `position: absolute` **一直在生效**，后来写的 `grid-row` 改不动它，所以看起来「怎么调都不对」。
- **改版式前先数一遍同名规则有几处**：
  ```bash
  node -e "const s=require('fs').readFileSync('src/skin-bold.css','utf8'); let n=0,a=-1; while((a=s.indexOf('.tpl-words {',a+1))>=0)n++; console.log(n)"
  ```
- 去重脚本按「选择器 + 花括号配对」整块删，会**切断带逗号的多选择器和 `@media` 块**（CSS 报 `Unexpected "@media"`）。要么先做括号配对校验，要么用**行号**精确替换。

### 9.3 SVG filter

- `<svg width="0" height="0">` 里的 filter 会被 Chromium 判失效 → 改成 `width="1" height="1"`。
- filter 原语里放 SMIL `<animate>` 会让整个 filter 判失效。
- **必须用内联 `style={{ filter: 'url(#id)' }}`**——样式表里写 `filter: url()` **不命中**，`document.styleSheets` 遍历也查不到这条规则。
- filter 元素挂到 `body` 上，不要放在被 `clip-path` / `overflow` 裁的容器里。

### 9.4 媒体

- **`<video preload="metadata">` 不解第一帧**，必须显式 `video.currentTime = 0.1` 才画出画面。
- **浏览器对 403 的媒体地址不会重试**。白名单变化后必须重新渲染元素（用 `mediaReady` 门控），否则格子永久空着。
- 178 个 `<video>` 同时挂会拖死窗口 → `IntersectionObserver`（`rootMargin: '280px 0px'`）+ `seen: Set`。
- **`media://` 的图画进 canvas 会跨域**，`getImageData` 抛 SecurityError（异常被 `catch` 吞掉后返回空数组，上层就退到兜底色）。修法：`image.crossOrigin = 'anonymous'`。
- 扫描排序必须 `localeCompare('zh-CN', { numeric: true })`，`readdir` 顺序由文件系统决定、不稳定。
- 重扫要用 `replaceMediaDir`（先清空该目录再填）。`mergeMedia` 只增不减，用户在资源管理器删掉的文件会一直留着、点开 404。

### 9.5 视频取色

`src/video-palette.ts` 里**必须 seek 到 `duration * 0.12`** 再抽帧。很多视频开头是黑场或台标，停在 0 秒取出来一片黑，等于没取。

### 9.6 全屏

- 真全屏要主进程 `win.setFullScreen(true)`，页面 `position: fixed` 只盖得住内容区，任务栏和窗口边框还在。
- **右侧那道白线的根因是滚动条**：内容高 1134 > 视口 1080，顶出 4px 滚动条，而 `position: fixed` 的定位基准不含滚动条，所以 `inset: 0` 只铺到 1916。修法：
  ```css
  html:has(.media-room.is-expanded),
  body:has(.media-room.is-expanded) { overflow: hidden; }
  ```
- **顺序必须是「先窗口、后页面」**，细节见 §9.15。原来 `expanded` 一置真页面就铺满，而窗口要等主进程轮询才变——点一次全屏会跳两下。

### 9.7 探针（验证脚本）

- **探针页面必须用真实的 `dist/index.html`**。自建 `file://` 页会让 `media://` 的视频报 `error 4`，误导判断。
- **探针必须在主进程先 `allowDir` / `allowFile` 再 `loadFile`**。页面发 `restore` 走 400ms 轮询，比图片请求晚；浏览器拿到 403 就不重试了。
- 探针灌 localStorage 后必须 `win.webContents.reload()` 再等 3 秒。
- 素材放 `%TEMP%` 会被系统清掉，**每次运行都要重建**，否则取色退回兜底色，截图看着像「取色算法错了」。

### 9.8 测量本身会骗人（这一轮踩了五个坑）

**「看着对不对」不算数，「量出来对不对」也可能被脚本 bug 骗。** 定值前先确认你在量的是同一块区域。

1. **截图分辨率会变，任何脚本都不许把宽高写死。** 同一个探针在不同 DPR / 显示器 / 窗口尺寸下截出的 PNG 尺寸不同（见过 3840×2160 和 1920×1080 两种）。写死宽高当 stride 用，读到不匹配的图时**不会报错**，只会行错位、`crop` 的 x 被 ffmpeg 钳到右下角，**输出看似正常的假值**。一律用 `tools/measure/pixels.cjs` 的 `load()`（内部走 ffprobe）。

2. **`cqw` 的基准跟着元素走，不是固定的。** 实测全屏 1920×1080 下：
   ```
   .template-collage   上 1cqw = 19.2px  （画布宽的 1%）
   .tpl-block-panel    上 1cqw = 5.55px  （面板宽 615 的 1%）
   .tpl-tag            上 1cqw = 5.55px  （它没有 container-type，继承面板的）
   ```
   所以同一个 `3.0cqw` 写在面板里是 16.6px、写在画布级元素上是 57.6px，**差 3.5 倍**。标题字号改错过一次就是这个原因。

3. **弧顶是 y 最小，不是 y 最大。** 面板弧向上鼓，用「y 最大」取到的是面板左下角。踩过一次，拟合出 `R=182` 全错（正确值 321.1）。

4. **按颜色逐列扫面板底边会被唱片照片污染。** 唱片里有与面板色相近的像素，采样点会掉进去，拟合出 `R=242`。**必须用连通域掩码**（`flood()` 返回的 `mask`）逐列取最低行，不能只返 bbox。

5. **拟合窗口不能太窄。** 面板宽的 0.62 倍拟出 `R=242`，0.75 倍拟出 `R=321.1`（正确）。Kasa 法在短弧上病态。

6. **文字带扫描窗口别撞进徽标胶囊。** 徽标的金色字母在亮度阈值下会被当文字。早期 `words-band` 模式用 `x 66.5..90%`，被污染成一个假的「8.40% 墨高」合并带。窗口右边界收到 **85%** 才对。

7. **胶囊宽度用颜色找不可靠，试了三次全失败。**
   - 「低饱和 + `r>95`」→ 量出宽 34%（整块面板都算进来）
   - 「连续 ≥70px」→ 19%（倒影层低对比渐变被算进来）
   - 限定窗口到 x86..99% → 10.07%（准值 7.30%，面板外 JPEG 噪点也是低饱和亮色）

   **结论：胶囊准值只读 DOM**（`tools/probe/geo.cjs` 的 `tag` 项），像素侧只用 `gold.cjs` 的 `STAR_BBOX` 当上界交叉验证。

8. **`goldBands()` 之类返回的是裁切图内坐标，不是原图坐标。** 打印时必须加裁切偏移。曾把它当绝对坐标传进去，两版结果不一致、白查一轮。

### 9.9 两色乌鸦：路径是怎么描出来的

原始 logo `docs/images/00-logo.png` 本身就是两色的（实测直方图：`rgb(33,42,50)` 占 2.73% 是身体、`rgb(93,108,120)` 占 1.09% 是翅膀亮区，其余 72% 是透明区，其 RGB 也是 0,0,0）。`ravenPath` 当年只描了 alpha 通道的整体剪影，所以填不出两色。

- `src/raven.ts` 的 `ravenWingPath`：标出亮色像素（`a>200 && r>60 && r<140 && b>70`）→ 全画布 4 邻域取最大连通域 → 逐行取左右边界 → 每 **5 行**一个点，先右边界向下、再左边界向上闭合。（每 12 行一个点时边缘是锯齿状。）
- **坐标映射是 `viewX = 25 + (px - 51) / 2`**：原图 1332×1204，alpha 包围盒 `[51,50]-[1284,1156]` 正好是 `ravenBox`（原点在 25,25、617×553）的两倍。**漏掉 `+25` 会让整块翅膀向左上错位、盖到鸟脖子上。**
- 着色：身体 `var(--tpl-panel)`、翅膀 `color-mix(in srgb, var(--tpl-bar) 65%, var(--tpl-panel))`。**不能直接用 `var(--tpl-bar)`**——那正是乌鸦脚下的底色，翅膀会和背景糊成一个洞。
- **路径里的加号必须在单引号外面**。第一次写入时每行写成 `'… L356 177 +'`，那个 `+` 成了路径数据的一部分，SVG 解析到那里就断，翅膀只剩 85 个字符、几乎是一个点——现象就是「还是单色」。`tools/probe/raven.cjs` 量 `d` 的长度与末尾即可发现（正常的 `dLen` 是 2121）。

### 9.10 面板上半：环境音状况

原来那四行英文（`For more information about / This Video / please read the / introduction`）和它的翻转倒影，是给**视频**用的说明文字（用户原话：「这个是我做视频用的，软件上展示这个就没什么价值了」）。现在换成：

```
AMBIENCE                        ← 标签，与信息条三个标签同一套度量（1.32cqw / 0.14em / 0.72）
Rain · Fireplace · Distant Traffic   ← 在场且没被静音的环境音名字，Playfair 3.15cqw
3 层 · 让出 18 dB                ← 层数 + 最深的那一层让了多少
```

- 数据来自 `src/App.tsx` 的 `ambienceStage`（`useMemo`）：`cabinet.ambience` 过滤 `cabinet.muted` → 映射成 record → `depth` 取**最深那一层**而不是平均值。三层里一层让 18 dB、两层让 6 dB，耳朵听到的是 18 dB。
- 静音层不出声，不计数——算进「3 层」就是谎话。
- 没在叠环境音时传 `null`，**整块不渲染**，不留空壳撑版面。
- 倒影用 `transform: scaleY(-1)`，不像旧版那样在 JSX 里把字倒着写一遍（那样 `aria-hidden` 之外还得维护两份文案）。
- 为什么不放曲目信息：用户否决第一方案的原话是「那是不是有点重复了和信息栏」。信息条已有 TITLE + PLAYLIST。

### 9.11 唱片：自转与换碟

**自转**：`@keyframes tpl-disc-spin` 早就写在 `src/skin-bold.css` 里，但**没有任何规则引用过它**（`grep spinning` 零命中），所以唱片一直不转。补上之后还有个坑：唱片靠 `transform: translate(-50%, -50%)` 居中，keyframes 里若写 `transform: rotate(...)` 会把居中整条替换掉、碟跳到右下。所以旋转走**独立的 `rotate` 属性**（与 `transform` 相加，不覆盖）。

**换碟**：新碟从 `-90°` 转回来、`scale 0.94 → 1`、淡入，520ms `cubic-bezier(.22,.61,.36,1)`；同时一道高光从左扫过 300ms。不位移、不改版式尺寸——唱片和面板的圆弧咬得很紧，一动就露缝。

触发方式：`src/TemplateStage.tsx` 把 `key` 挂在唱片身份上（本地是 `local:${id}`、外部是 `ext:${app}|${title}`），换碟时 React 重建节点，动画自然重播一次。**不需要状态类**，也就没有「什么时候把类删掉」的残留问题。

两条容易踩的：

1. **启停用 `animation-play-state`，不要加/删 `animation`**。原版 `.vinyl` 就是这么做的：暂停时碟停在当前角度，续播从那个角度接着转，不会跳回 0°。`animation` 简写在两处都写会互相顶掉。
2. **入场 keyframes 只写 `from` 的 `opacity`，让 `to` 取元素自己的值**。写死 `to { opacity: 1 }` 会让待机态那 0.72 的透明度被动画锁死——实测 `opacity` 一直是 1，待机碟永远是亮的。

`tools/probe/disc-swap.cjs` 就是量这两条的：待机时 `animationName` 应为 `tpl-disc-enter, tpl-disc-spin`、`animationPlayState` 为 `running, paused`；节点重建后 80ms 应在入场中（`rotate` 负角度、`opacity` < 1）；680ms 后 `getAnimations()` 里只剩自转、`rotate` 回到 `none`、`opacity` 回到 0.72。

### 9.13 `media://` 必须自己回 206，否则 4K 视频起不了播

用户 m04634 报「有些视频不能放映，或者放映有破损」：`Ocean大海`（88MB）与
`Tokyo CyberPunk City Ambience Rain On Window`（121MB）。

**根因**：协议体原来只有一行

```js
return net.fetch(pathToFileURL(target).toString());
```

`net.fetch` 会把请求里的 `Range` 头**整个丢掉**。探针实测（`tools/probe/media-range.cjs`）：
要 `bytes=0-1023`，回来的是 `200` + 完整的 92544419 字节。

对 `<video>` 的后果有两层：

1. 拖不动进度条；
2. **`moov` 在文件尾的 MP4 永远起不了播** —— ffmpeg 默认把索引写在最后，Chromium 必须先读到索引才知道时长和关键帧位置，只能整段下完再说。121MB 走这条路，表现就是转圈、花屏、只出几帧。

**注意别被文件结构骗了**：用户点名的两个里，`Ocean` 的 `moov` 其实在**开头**（faststart），只有 `Tokyo` 在 99.99%。所以「哪几个文件坏了」不是靠 `moov` 位置判断的——真原因是所有视频都没走 Range，只是索引在尾部的那个最明显。

**修法**：新建 `electron/media-response.cjs` 自己实现 RFC 7233 的单段 Range。

| 请求 | 响应 |
|---|---|
| 无 `Range` | `200` + `Content-Length` / `Accept-Ranges: bytes` |
| `bytes=a-b` | `206` + `Content-Range: bytes a-b/size` |
| 起点越过文件尾 | `416` + `Content-Range: bytes */size` |
| 多段 / 乱写 | 退回 `200`（不假装支持） |

读文件用 `fs.createReadStream(file, { start, end, highWaterMark: 1 << 20 })` 包成 web `ReadableStream`，边读边推，不整段进内存。

实测（`tools/probe/video-play.cjs`，修复后）：

```
tokyo (moov 尾, 126.8MB): metadataMs 33, canPlayMs 17, totalMs 54, readyState 4
ocean (moov 头, 92.5MB):  metadataMs 16, canPlayMs 16, totalMs 40, readyState 4
```

放映页里（`tools/probe/screen-video.cjs`）两支都是 `readyState 4 / 3840×2160 / paused false / muted true / error null`，截图无破损。

**用户报的「第一次点放映卡一下」和这条是同一个根因**。切页本身量下来是干净的：`PerformanceObserver` 抓不到任何 longtask，`mountMs 0`、`firstFrameMs 0.1ms`、rAF 最坏帧间隔 34.5ms、stalls 0（`tools/probe/first-jank.cjs`、`jank.cjs`）。卡的是 4K 首帧解码——先把 121MB 下完才能出第一帧。

**测试**：`tests/media-range.test.ts`。**坑**：`tests/` 是 ESM、`electron/` 是 CJS，必须 `const require = createRequire(import.meta.url)` 再 `require`，否则报 `require is not defined in ES module scope`。而且这种错 `npm test` 只显示 `'test failed'`，要 `node --test tests/xxx.ts` 才看得到真实原因。

### 9.15 点一次全屏为什么跳两下，以及怎么修掉的

**现象**（用户原话）：「点击全屏按钮，它会首先在软件页面内全屏再全屏」。先是画面在**当前这个窗口里**撑满（1906×1017），过一会儿窗口才真的变大（2560×1440），像跳了两下。

**这是两件不同步的事**：

1. 页面铺满——`src/MediaRoom.tsx` 里 `expanded` 一置真，React 重渲染，CSS 立刻让 `.media-room.is-expanded { position: fixed; inset: 0 }` 铺满**当前视口**。这是同步的，点击那一帧就发生。
2. 窗口真全屏——`setWindowFullscreen()` 只是往 `__ravenMediaOutbox` 里推一条动作，主进程每 **400ms** 轮询一次才取走，再 `win.setFullScreen(true)`。Windows 的全屏过渡本身还要几十毫秒。

原来这两个是「先后」关系：先 1 后 2，中间那一百多毫秒里，页面已经在一张没变大的窗口里铺满了。

**修法分两步，缺一不可**：

- **敲门**（`electron/media.cjs` + `src/media.ts`）：推完动作就 `fetch('media://local/__knock', { method: 'HEAD' })`，协议处理器在**白名单判断之前**认出这个伪路径，直接 `bridge.poke()` 让主进程立刻 `take()` 一次。实测主进程收到请求 **95ms → 21ms**。
  - 为什么借 `media://` 而不加 preload：页面是 `sandbox: true` 且刻意没有 preload（见 `electron/now-playing.cjs` 文件头「页面永远是被动的一方」）。为一个时序问题放开沙箱不值。
  - **204 不能带 body**：`new Response('', { status: 204 })` 会抛 `webidl.errors.exception ... initializeResponse`，必须用 `new Response(null, ...)`。
- **先窗口、后页面**（`src/MediaRoom.tsx` + `src/fullscreen-timing.ts`）：`toggleFullscreen` 先推全屏请求，再用 `afterResize()` 用 rAF 盯 `window.innerWidth/innerHeight`，**尺寸真的变了**才 `setExpanded`。250ms 兜底（主进程没响应也不能让点击没下文），返回的取消函数保证连点时前一次的等待作废。
- 顺带删掉 `useEffect(() => { setWindowFullscreen(expanded); }, [expanded])` —— `toggle` 已经推过一次，这个 effect 会推第二次，主进程那边 `setFullScreen` 收到同值仍会重走一遍 Windows 过渡。
- 冷却锁 `canToggle(lastAt, now)`：`TOGGLE_COOLDOWN = 320ms`。**`lastAt` 初值必须是 `-Infinity` 不能是 `0`**——页面刚起来时 `performance.now()` 也可能很小，拿 0 当「没点过」的哨兵会把第一次点击挡掉。

**实测（`tools/probe/fullscreen-jump.cjs`，1920×1080 窗口）**：

```
修前 t=0 1906×1017 卡片 → t=20 1906×1017 满屏 → t=138 2560×1440 满屏   （两跳）
修后 enter t=0 1906×1017 卡片 → t=4 2560×1414 卡片 → t=24 2560×1440 满屏
     leave t=0 2560×1440 满屏 → t=15 1906×1043 满屏 → t=21 卡片 → t=43 卡片
main  marks: [{enter, t=2}, {leave, t=1407}]     每个方向只有一个事件
```

「小尺寸满屏」那一帧彻底消失。退出方向留了一帧「满屏跟着窗口一起缩」，视觉上连续，是对的。

**探针必须 build 后才能跑**：`tools/probe/harness.cjs:132` 加载的是 `dist/index.html`，改完源码直接跑量到的是旧代码（我第一次就白高兴了一场）。

**测试**：`tests/fullscreen-timing.test.ts`（8 条：尺寸变化即执行 / 超时兜底 / 只执行一次 / 取消后不执行 / 进出都是先窗口后页面 / 只变宽或只变高也算 / 冷却期内挡到点放 / 首次点击不被挡）。`afterResize` 的依赖是注入的——组件里没法验证时序，注入假时钟和尺寸表才能把每条路径走完。

### 9.16 FOCUS 进度条为什么「看起来没在动」

**现象**：用户连问两次「这个横线是有什么作用，是一个进度条的作用吗，我怎么感觉没有在动」。

**它画的是什么**：本阶段**剩余比例**。满格=刚开始，缩到底=本阶段结束。`src/MediaRoom.tsx` 每 800ms 读一次 `window.__ravenFocusSnapshot`，算出 `remaining / total` 交给 `src/TemplateStage.tsx` 的 `.tpl-focus-bar > span` 的 `style.width`。

**第一层原因（不是 bug，但确实不显眼）**：25 分钟的番茄钟，实测进度条 387.2px 宽，每分钟走 **15.49px**，每 800ms 一拍只走 **0.207px**——走满 1 像素要 3.9 秒。绑定本身是通的（50%→193.59px、4%→15.48px，连采 242 帧平滑爬升），只是这个尺度上「线在变短」这件事人眼根本注意不到。原线高只有 1.88px。

**第二层原因（这才是真 bug）**：`src/skin-bold.css:4231` 有一条

```css
.media-room.is-expanded .tpl-fields span { font-size: 17px; max-width: 30ch; }
```

它是给文字格防溢出的，但选择器**也命中了进度条内层那个 `span`**。30ch 在 17px 下 ≈ 294.77px，于是整条线最宽只能到 `294.77 / 387.2 = 76.13%`。剩余比例在 76% 以上（刚开工的大半个阶段）时线头**钉死不动**，看起来就像根本没用。

这个 bug 藏了很久，因为 76% 的线看起来完全正常。

> **教训**：写 `X span` 这种后代选择器时，先想清楚 X 里除了文字还有没有别的 `span`。这里的 `span` 是进度条的填充层，不是文字。踩一次就够了——所以修法是在进度条那条路径上显式写 `max-width: none`，而不是去动那条全局规则。

**修了两处**（`src/skin-bold.css` `.tpl-focus` 一带）：

1. 进度条 `> span` 加 **`max-width: none`**（外加 `position: relative` 供圆点定位），并用 `background: color-mix(in srgb, currentColor 80%, transparent)` 代替原来的 `opacity: 0.8`——`opacity` 会把子元素（圆点）一起压淡。
2. 让它**更容易被看见**：线高 `0.16cqw → 0.22cqw`（1.88px → 2.58px），`overflow: hidden → visible`（否则探出线头的半个圆点被裁掉，看着像毛刺），并在 `> span::after` 画一颗端点圆点 `0.52cqw`（**实测 6.13px**）。
   - 圆点第一版写 `0.34cqw` = 4px，和 2.58px 的线几乎分不开，等于没加。
   - 选端点圆点而不是「离散刻度格」：刻度只说明「这是有刻度的」，对「看得出在动」没帮助，还多一处视觉噪音。有形状的小点缓慢平移，比线段变短更像一个进程。

**修后实测**（`tools/probe/focus-bar-motion.cjs`）：

```
atFull  styleWidth 100%  ratio 100  fillPx 387.19  dotPx 6.13
atHalf  styleWidth  50%  ratio  50  fillPx 193.59
atTail  styleWidth   4%  ratio   4  fillPx  15.48
motion  frames 240  min 15.48  max 387.19
pxPerMinute 15.49  pxPerPoll 0.207  secondsPerPixel 3.9
```

**探针写过三版才对**，坑在「等多久才算稳」：

- 固定 `wait(2000)` 会读到过渡中间态（`styleWidth 100%` 但 `ratio 76.13%`），于是得出「它被钳死了」的错误结论——而实际上当时正在过渡。
- 改成轮询后，**第一拍读到的是上一档的值**，而上一档自己也自洽（`styleWidth` 与 `ratio` 相等），会立刻被判成「已稳定」。表现是三档都报 `100%`。
- 最终：设完快照 **先 `await wait(1800)`**（800ms 轮询 + 800ms 过渡，最坏 1600ms），再连读；对不上时把 `ratios: [...new Set(seen)]` 带出来——**完全不变 = 被 CSS 钳死，还在变 = 只是没等够**，一眼分得清。

**另外**：`tools/probe/focus.cjs` 在「真被钳住」的状态下看起来一切正常（`fillWidth 85%`、`fillRect w 20.4%`），因为它只量一次静态布局。判「动没动」必须连采多帧。

### 9.17 控制条为什么「看着像在信息条下层」，以及大理石胶囊怎么改的

用户原话（m06000）：「这个面板的大理石纹部分我觉得还是需要进步一下，现在看着就有点像分型杂色原来的样子，你看看能不能用高光还是什么办法把他变得好看一点，然后我全屏后发现底下的控制栏为什么在下层不在最上层看着有点别扭」。

#### 控制条：**不是层级问题**

先用 `tools/probe/chrome-z.cjs` 在控制条横向 5 个点（6%/30%/50%/70%/94%）上 `document.elementFromPoint` 问「最上层是谁」——**5 个点全部 `inBar: true`**（分别是 `b`、`div.theater-copy` ×3、`button.theater-overlay-toggle`）。层级快照也不支持「被盖住」：`.media-room` 是 `z-index:60 position:fixed`，`.theater-bar` 在它里面，`.tpl-block-bar`（版式信息条）只有 `z-index:8`。

**真正的原因是没有边界，不是没有层级。** 原样式是

```css
.media-room.is-expanded .theater-bar {
  left: 0; right: 0; bottom: 0; border-radius: 0;
  background: linear-gradient(to top, #000000d9, #00000000);
}
```

贴满屏宽、贴齐底边、往上淡出——它和画面**连成一片**。而版式信息条占画面下部 25%（`bar 1.77/71.11/63.02/25.37`），控制条那 62px 正好压在信息条底边（实测 `overlap: 24`px），于是读成「信息条表面浮了一层脏东西」。**再高的 z-index 也救不了**：没有轮廓、和背景同色渐变、还贴着底边的东西，视觉上就是背景的一部分。

改用 `chrome-shot.cjs` 做过对照实验：给控制条换上实心底 + `backdrop-filter` 再截一张，**两张图几乎一模一样**——证明"加深底色"这个方向根本不对，问题在形状不在颜色。

**改成浮起的玻璃胶囊**（`src/skin-bold.css:3389` 一带）：

```css
left: 26px; right: 26px; bottom: 20px;   /* 离底留缝，不与屏幕边缘共用边界 */
border-radius: 999px;                     /* 四角全圆，自己是一个整体 */
background: #0b0f14e0;
backdrop-filter: blur(22px) saturate(1.18);
box-shadow: inset 0 1px 0 #ffffff24, 0 10px 30px #00000059;
```

- 顶部 `inset` 高光等于给胶囊一个上表面，和面板大理石胶囊的高光是同一套语言，不额外发明"发光边框"。
- `@supports not (backdrop-filter: blur(2px))` 退回实底 `#0b0f14f2`，否则半透明底透出画面会把白字搅花。
- **同时要改 `:4531` 那条**：原来那里写 `bottom: 0; border-radius: 0`（通栏黑带时代"贴底不留缝"的判断），改成胶囊之后会把圆角切掉，所以只保留 `margin-bottom: 0`。

实测：`chrome [26,1010,1868,50]`，与信息条 `overlap: 32`px（悬浮在它上面，这是对的）。条内 11 个元素全部 `inside: true`，没有被圆角切掉或被挤出胶囊。

#### 大理石：从「电视雪花」改成「被揉弯的条带」

原来 AE 那层照搬成 `feTurbulence type="fractalNoise" baseFrequency="0.052" numOctaves="10"` + 纯白底 + soft-light——**就是一片均匀噪点**，用户判断准确。

真大理石是**被揉弯的条带**：沉积层的平行条纹被地壳挤压成弯曲脉络。所以正确做法不是"生成噪声"，而是**先画直条纹，再用低频噪声把它揉弯**（`feDisplacementMap` 干的正是这件事）。

管线住在 `src/marble.ts`（从 `TemplateStage.tsx` 抽出来的，纯字符串，可测）：

```
repeating-linear-gradient（::before 画的直条纹，黑白交替、间隔 7/9/11/14/31/33/38/47/52/74/79px）
  → feTurbulence baseFrequency="0.006 0.019" numOctaves="4"   （横向频率低 → 条纹主要被左右挤）
  → feDisplacementMap scale="46"
  → feGaussianBlur stdDeviation="0.9"                          （石头没有硬边）
  → feComponentTransfer linear slope=1.55 intercept=-0.28      （压成亮脉 + 暗底）
  → feBlend soft-light 叠一层 saturate 0 的细颗粒
```

三个不能动的性质（`tests/marble.test.ts` 5 条守着）：

1. **顺序必须是 位移 → 模糊 → 对比**。先糊再位移会把脉络拉成糊条。
2. **位移场横向频率必须低于纵向**（`0.006 < 0.019`）。`numOctaves` 不能超过 4——层数多了又退回细碎噪点，那正是要改掉的东西。
3. **条带必须同时有亮有暗**。只放白条纹 + soft-light 揉出来仍是一层均匀提亮，看着像磨砂塑料；改成黑白交替 + `overlay` 才有"石头"的体积。

另外新增 `.tpl-tag::after` 单独一层**方向性高光**（`linear-gradient(160deg)` + 左上 `radial-gradient` + 右下压暗，`soft-light`）。**必须与纹理分层**：纹理要过 SVG 滤镜，高光过了会被一起揉碎。

> **坑**：`filter` 引用失效是**静默的**——id 对不上时 computed 只是变回 `none`，屏幕上看不出任何异常，只是"胶囊表面平平的"。`tools/probe/marble.cjs` 专门报 `filterExists` 字段来发现这件事。

**探针坑**：`report()` 内部会 `app.exit(0)` 销毁窗口，所以**截图必须在 `report()` 之前**，否则 `PROBE_FAIL Object has been destroyed`。

### 9.18 石纹做成两种可选：浪脊与玉石，以及「像不像」怎么量

#### 参考图那块到底是什么（这一步错了四次，最后一次最贵）

8 倍放大（`tools/measure/ref-a.png` / `ref-b.png`）才看清：**边缘柔和、带方向的暗色晕块**，宽十几到三十像素，有明确走向。

#### 五条「测量骗人」（这一节最值钱的部分）

1. **采样位置错了**。`tools/measure/jade-stats.cjs` 只量胶囊左右两侧的无字窄带（6%~17% 与 83%~94%），那两条恰好是整块里**最均匀**的部分。拿边缘统计逼近整体，必然做出「均匀的糊」。
2. **放大片上的相关距离不能当原图像素**。`tag-ref.png` 是 134px 放大 5 倍，量出的相关半衰 x=29 / y=41，换算回原图只有 5.5 / 7.8。此前当成「团块十几到几十像素」，管线一直在做 50~200px 的周期——**差二十倍**。
3. **矩形裁片的四角污染统计**。胶囊是圆角，四角落在深色面板底（`#4a5363`，亮度 82）上。`tools/measure/hist-round.cjs` 按胶囊自身形状（左右各一半圆 + 中间竖条）造掩膜之后，我们那边的假峰 72 才消失。
4. **峰度判据是错的**。`feTurbulence` 只有单一尺度，分布天生接近高斯，峰度停在 8~17，做不出参考图的 3.33。为压峰度加第二尺度，反而把纹理做成斑点。
5. **直方图分不出「连成片」和「碎成点」**——这条是最后才发现的，也是结束死循环的那条。一片 100px 的暗团与 100 个 10px 的点，`mean / sd / skew` 可以完全一致。参考图暗区有 **90.8%** 连成大块，高 `sharp` 那版只有 74.2%。判据只能是**暗区的连通性**，见 `tools/measure/blobs.cjs`（阈值取中位数、4 邻接连通域标记，报 `largeShare` / 块数 / 等面积直径分位数）。

#### 三个静默出错（都不会报错，只会「看着不对」）

1. **`<feComposite operator="over">` 会把整张灰度图盖上去**，得到一层不透明灰，CSS 底色完全看不见。前十几版「怎么做都像海绵」的直接原因。要乘用 `operator="arithmetic" k1="1"`。
2. **`operator="in"` 会用 SourceGraphic 的 alpha 当遮罩**。`::before` 的 `background` 一旦是 `transparent`，整张纹理被乘成 0——现象是「换个底色，纹理忽然不见」。圆角裁剪由 CSS 的 `clip-path` 负责，滤镜里不需要它。
3. **`soft-light` 把垫色的作用吃光了**。`background` 从 `#606060` 调到 `#545454`，`meanRaw` 只从 135.18 动到 135.07，`texSd` 完全一样；而且它有幅度上限。**白底 + soft-light 只提亮不压暗，均值永远压不下来**（实测 158.8 对参考图 133.2）。
4. **多个 `feFuncX` 让 `feComponentTransfer` 静默失效**。想给三通道不同 intercept 做偏色，整段换成自闭合 `<feFuncR/>` 之后六档统计完全相同——`innerHTML` 走 HTML 解析器会把后来的兄弟节点吞成子节点，整段失效、不报错。**改页面里的 SVG 只能改属性值，不能重建标签结构。** 偏色只能靠 `feColorMatrix type="matrix"`。

#### 定稿管线（`src/marble.ts`）

两种石纹走**同一套函数** `bandMarkup(id, spec)`，差别只在传进去的参数表：
`sea` → `SEA_SPEC`，`jade` → `JADE_SPEC`。旧的 `seaMarkup` / `jadeMarkup` 已删除。

为什么能共用：用户 m09905 说「玉石这个色彩做的挺好，波浪这个不太明显，能不能也和玉石一样」。
旧浪脊走的是完全另一条路——`feTurbulence` 只当位移场，纹理本体是 CSS 的白条纹
`repeating-linear-gradient(20deg, …)` 加 `mix-blend-mode: overlay; opacity: 0.46`。
白色叠在白底上，对比度被底色吃掉，所以「不明显」。换成同一条滤镜管线之后两者
才真正可比：**都是「噪声的中值等值带」，只是频率与带宽不同**。

```
每层   ：feTurbulence 默认 turbulence → saturate 0 → feComponentTransfer type="table"
         表是 bandTable(lo, hi, width, 160 采样点)：
         val = hi − (hi − lo)·exp(−((x − 0.5)/width)²)
         feFuncA slope="0" intercept="1"（alpha 必须钉死）
         → 位移（共用一条 feDisplacementMap，scale 见下）→ feGaussianBlur
三层   ：主干 freq 最低、width 最宽、blur 最大；中枝次之；细枝最高频、最窄、最不糊
合成   ：两级算术加权（k1=0），最后一级权重和 = 1
收尾   ：feComponentTransfer 把 mix 映射成亮度系数（slope=amount, intercept=1−amount·center）
最后   ：feComposite in="SourceGraphic" in2="lit" operator="arithmetic" k1="1"
         —— 与 CSS 算的底色相乘，只缩放亮度、不改色相
```

**为什么是「中值等值带」而不是折叠**：折叠 `pow(|sin(v·rings·π)|, sharp)`
出来的是**闭合的等值线圈**，挤在一起就是圆斑。噪声值恰好等于 0.5 的那条曲线
天然连续、能分叉、能铺满平面——这才是「树根」的形状。用户 m09592 要的正是这个。

两张参数表（改任何一格都要重新标定 `center` 与 `amount`，见下）：

| | `sea`（浪脊） | `jade`（玉石） |
|---|---|---|
| 主干 | `0.004 0.018` / width 0.180 / blur 3.2 / w 0.46 | `0.007` / width 0.150 / blur 2.8 / w 0.46 |
| 中枝 | `0.0088 0.0396` / width 0.034 / blur 1.0 / w 0.32 | `0.030` / width 0.022 / blur 0.85 / w 0.30 |
| 细枝 | `0.0152 0.0684` / width 0.014 / blur 0.5 / w 0.22 | `0.070` / width 0.009 / blur 0.40 / w 0.24 |
| 位移 | `0.004 0.018` / scale 58 | `0.007` / scale 66 |
| `amount` / `center` | 1.41 / 0.498 | 1.6 / 0.54 |


六个旋钮各自的职责，改之前先读：

- **`width` 决定丝有多粗**。`bandTable` 里 `val = hi − (hi − lo)·exp(−((x − 0.5)/width)²)`，`width` 是「离中值多远还算是这条丝」的半宽。三层必须**拉开一个数量级**（0.150 / 0.022 / 0.009）才从「龟裂」变成「有主次」；早期三层都用 0.02 上下，出来是一张破蛛网。
- **`freq` 决定丝的疏密**。玉石的细枝 0.070（≈ 14px 周期）是照 `tools/measure/vein-scale.cjs` 量的参考图丝间距 p50 8~9px 定的。**主纹越粗、频率必须越低**，否则粗丝会互相挤掉。
- **`blur` 逐层递减**（主干 2.8 → 细枝 0.4）。参考图的丝是**晕的**，主干不糊就会看到台阶；细枝一糊就消失了。这一条与浪脊版正相反，别照抄。
- **位移 `scale` 与位移场频率要配对**。太小出来是规整的同心圈，太大散成斑；频率再低只会整体平移而不揉弯。
- **末尾一级把中性灰换算成「亮度系数」**：`m = amount·(mix − center) + 1`，`mix` 等于 `center` 处正好乘 1、不改整体明暗。**`center` 必须实测，不能假设 0.5**——等值带版实测纹理均值约 0.54~0.56（`tools/probe/stone-mix2.cjs` 把管线在 `mix` 处截断直接量）。按 0.5 算，均值落在 1 以上，一大片被钳在 1：调 `amount` 只改「被钳面积」，`sd` 从 0.7 到 0.8 几乎不动，只有 `skew` 在翻——这就是「怎么调都调不动」的真因。
- **`center` / `amount` 跟参数表绑定，不能跨风格照抄**。浪脊纹理均值 0.498、玉石 0.56；把玉石的 0.54 抄给浪脊，`lit = 1.6×(0.848−0.54)+1 = 1.49` 被钳在 1，屏幕一片白（实测 `mean 205.5 / sd 4.55`）。**换风格时这两个数一定重标。**
- **滤镜里不许有颜色，颜色来自 `SourceGraphic`。** 用户 m09087 原话：「这个胶囊不是分型杂色吗，也就是说它本身是没有色彩的，他是根据面板的颜色来变色的」。参考图那块偏蓝（`blueMinusRed +24.3`）本来就是**面板的蓝透过半透明胶囊**上来的，我为了数值对上，把蓝写死进了 `feColorMatrix` 的三个 offset。后果：六档面板实测 `dR=dG=dB=0`，胶囊纹丝不动。现在的做法是末尾与 `SourceGraphic` 相乘——只缩放亮度、不改色相，颜色恒等于底色。

CSS 侧（`src/skin-bold.css` 的 `.tpl-tag::before`，**两种风格共用一条规则**）：`background: hsl(from var(--tpl-panel) h s calc(l * 1.6))`、`filter: url(#tpl-marble)`、`mix-blend-mode: normal`、`opacity: 1`。`::after` 高光两种风格共用同一档——分开写会让换石纹时胶囊亮度跳一下。

底色为什么要用**相对颜色语法抬明度**而不是混白：`color-mix(#fff 34%, panel)` 会同时提亮**和**褪色，蓝面板下 `blueMinusRed` 只剩 11.9（参考 24.3）——「又亮又蓝」这两件事混白做不到同时成立。`hsl(from … h s calc(l * 1.6))` 只抬明度、色相与饱和度原样保留：实测 `blueMinusRed` 27.0 / `mean` 128.5（参考 24.3 / 130.1），暖色面板下 −24.3，跟色幅度与面板自身一致（`stone-tint.cjs`）。


`opacity` 取 1 的理由：滤镜末尾已经把均值与跨度都对到参考图，这里再乘系数只会把对好的数又推开。**纹理的「多重」在滤镜末尾定，「能不能看见」才是 CSS 这层的活**——现在两者重合。

#### 当前实测（口径 `node tools/measure/hist-round.cjs <图>` 与 `blobs.cjs`）

```
                  mean    sd   skew   暗区   大块占比  blobs  直径 p95  蓝红差
参考图 tag-raw    130.1  12.22  −0.55  0.498   0.908     30     33.8   +25.0
实机 j33-01-jade  124.0  11.64  −0.69  0.499   0.884     35     27.2   +64.2
```

#### 探针写法：别用正则改页面里那份 markup

早期试过 `source.outerHTML.replace(/baseFrequency="…"/)`，六档全报 `freq pattern missed`——`outerHTML` 序列化出来的属性顺序、自闭合写法、空白都和源码串不一致。**换个写法去猜序列化结果，一定还会再错。**

正确做法（`stone-jade74.cjs` / `stone-jade76.cjs`）：按 `marble.ts` 的同一套模板自己拼，然后**先拼一份默认参数和页面里那份做结构签名比对**（`templateMatches`），对不上就不截图直接报错。签名是「标签名 + 排好序的属性」，不能比原始字符串：浏览器把 `<feTurbulence/>` 序列化成 `></feTurbulence>`，实测 1672 vs 1471 字符。

另一个坑：`applyScript` 里同一作用域出现两次 `const s` 会让 `executeJavaScript` 只回一句 `PROBE_FAIL Script failed to execute`，**渲染端真实异常不回报**。语法预验用 Node 的 `new Function('return ' + code)` 比起 Electron 快得多。

#### 切换入口：在胶囊上点，不在配色面板里

用户 m09905 原话：「这个直接做成在胶囊上点击就切换吧，别在调色板显示了」。

- `src/marble.ts` 导出 `nextStoneStyle(value: unknown): StoneStyle`，按 `stoneStyles` 顺序循环。
- `src/TemplateStage.tsx`：`.tpl-tag` 从 `<div>` 改成 `<button type="button" onClick={onStone} disabled={!onStone}>`，`aria-label` 随当前风格变化（`'石纹：玉石，点击换浪脊'`）。**用 `<button>` 而不是给 div 挂 onClick**：键盘用户能 Tab 过去、Enter/Space 直接触发，不用另写一套按键处理。
- `src/MediaRoom.tsx`：`const cycleStone = useCallback(() => { setTone(prev => ({ ...prev, stone: nextStoneStyle(prev.stone) })); }, []);`，两处 `<TemplateStage>` 都传 `onStone={cycleStone}`。

### 9.19 唱片上左右滑动切歌

用户 m10369：「现在感觉差不多了，我想再加一个左滑右滑唱片能切换上一曲下一曲的功能」。

规则只有几行，但边界条件多，所以抽成纯函数 `src/disc-swipe.ts`，组件只负责把指针坐标喂进去。**组件里没法对着真实手指验证，抽出来测试才能拿一串坐标把每条边界走一遍。**

三个数是量出来的：

- **阈值 48px**：唱片直径约 390px（全屏 1920 时），48px 是它的一成多一点。再小会把按下时的轻微位移当成切歌；再大得横跨小半个屏幕才生效。
- **斜率 1.4**：纵向分量超过横向的七成就不算横滑。少了这条，斜着往下一划会既像「翻页」又像「切歌」。
- **跟手上限 16px**：面板挖出的圆洞只比碟大 **20.5px**（半径方向，§9.15 那轮量的）。超过这个数碟就撞上洞边，看着像穿模。

方向：**左滑 = 下一曲**（手指往左推，拿走的是当前这张，顶上来的自然是下一首），右滑 = 上一曲。

#### 三个实现要点

1. **跟手位移走 `--disc-drag` 变量，不写 `transform`**。唱片身上挂着居中（`translate` 属性）与旋转（`rotate` 属性），`transform` 会把居中的那半截顶掉——和 §9.11 旋转中心是同一个坑。CSS 侧是 `translate: calc(-50% + var(--disc-drag, 0px)) -50%`。
2. **判断「正在滑的那根手指」用 ref 不用 state**。浏览器一帧内可能连发几个 `pointermove`，React 批处理之后它们读到的还是上一次的 state，前几笔位移被整段丢掉——手一甩就有一百像素落在同一帧里，那是能感觉到的。探针第一次跑出 `--disc-drag` 恒为 `0px` 就是这个原因。state 只留给渲染（`is-swiping` 类、变量值），判断一律看 ref。
3. **`.tpl-disc-layer` 整层是 `pointer-events: none`**（它只是占位的画），手势能不能进来由 `.tpl-disc.is-swipable` 单独打开：`pointer-events: auto; touch-action: none; cursor: grab`。`touch-action: none` 不能少，否则触屏上浏览器把横滑当滚动吃掉。

#### 不能切的时候不接指针

`src/App.tsx` 的 `canSkipDisc = cabinet.lineMode ? hasTrack(nowPlaying) : cabinet.queue.length > 1`，为假时 `onPrevTrack` / `onNextTrack` 都传 `undefined`，`TemplateStage` 里 `swipable` 为假 → 不加 `is-swipable` 类 → `pointer-events` 保持 `none`，滑上去什么都不会发生，也不会出现抓手光标。

#### 探针与测试

- `tools/probe/disc-swipe.cjs` 量三段：能切时的样式与跟手钳位、松手回位、不能切时的 `pointer-events: none`。实测 `liveMidDrag.drag = "-16px"` / `translate = "calc(-50% - 16px) -50%"`，松手回 `0px`；`idle.pointerEvents = "none"`。
- **必须用页面内 `dispatchEvent(new PointerEvent(...))`**：`sendInputEvent({type:'mouseDown'})` 产生的是 mousedown，**不是** pointerdown，React 的 `onPointerDown` 收不到，量到的永远是「没反应」。这条和长按拖拽那轮是同一条结论。
- **一个进程只能注册一次 `media://`**：第二次 `launch()` 会报 `Failed to register protocol: media`，而 `close()` 是 `app.exit(0)`。所以探针里两种状态靠改 localStorage + `reload()` 切换，不起第二个窗口（和 `ambient.cjs` 同样的做法）。
- 探针里造队列必须**同时造 `records`**：`sanitizeCabinet` 会用 `records` 过滤 `queue`，光写 `queue: ['fake-a','fake-b']` 会被整条丢掉，量到的还是「切不了」。
- `tests/disc-swipe.test.ts` 10 条：阈值内不触发 / 刚好 48 触发 / 左滑 +1 右滑 −1 / 纵向占优不触发 / 纵向七成以内仍触发 / 跟手同号且被压小 / 钳在 ±16 / 上限可调 / `moveSwipe` 不改起点（来回晃不会越算越偏）/ 刚按下那一帧不触发。

### 9.20 桌面放映窗：把舞台单独摆到桌面上（**已被否决，留作教训**）

> 用户 m11232 原话：「抱歉，墨羽，我没理解你做的这个是什么，我的目的是 wallpaper 不是有很多场景类壁纸吗……所以我想的就是学习 folia 做一个透明的，这样就可以直接用桌面的场景壁纸了」。
>
> **这一节做出来的是「新开一个不透明的全屏窗口把舞台搬过去」，方向不对。** 代码骨架（多页入口、桥、窗口模块）后来全留着用了，只是把窗口改成透明、把内容改成「只放组件」。取舍改到了 §9.21。

用户 m10720：「现在咱们整完了，可以考虑 folia 那个事情了」。调研 Folia（`github.com/chthollyphile/folia-major`）之后确认走 **A 方案：一个独立的全屏无边框窗口**，不是 B 方案（真·壁纸层）。

#### 为什么不做真·壁纸层

Folia 的壁纸模式是把窗口 `SetParent` 到 Windows 的 WorkerW，窗口落在**图标层之下**。代价是那个窗口物理上收不到鼠标（图标层挡着），要在 Raw Input / CGEventTap 那一层旁路抓桌面点击、换算 DIP 坐标、再 `sendInputEvent` 注入回渲染进程——几千行，还要处理多屏、DPI、全屏应用。**为一个「在桌面上放块画面」的功能抄这一整套不值。**

顺带纠正两个常见误解：

- **不需要常驻 Rust 进程**。`koffi` 是带预编译二进制的 FFI 库，不用编译工具链；Windows 拿窗口句柄就是 `win.getNativeWindowHandle()`。
- **Electron 没有「压到最底层」的 API**。Windows 上那是 `SetWindowPos(HWND_BOTTOM)`，要 FFI。所以这一版**不做 alwaysOnTop**，也不假装能沉底——它就是一个普通窗口，被别的窗口盖住是正常行为，要看的时候最小化别的窗口，或者再点一次把它提到前面。

#### 结构：三个新文件 + 五处改动

| 文件 | 干什么 |
|---|---|
| `desktop.html` | 桌面窗的入口。和 index.html 同一套 CSP，**没有开屏动画**——这个窗口是用户点了才出现的，再放 logo 只会先黑一块。 |
| `src/desktop.tsx` | 只渲染 `<TemplateStage>` 一块，套上 `.media-room.is-expanded > .media-theater > .theater-screen` 三层外壳。 |
| `src/desktop.css` | 窗口级的几条：`html,body` 归零、`.desktop-stage { position: fixed; inset: 0 }`。 |
| `src/desktop-bridge.ts` | 两个渲染进程之间的通道（下面单说）。 |
| `electron/desktop-stage.cjs` | 窗口的建立 / 摆放 / 销毁，以及每 200ms 搬运一次状态。 |

改动：`vite.config.ts` 加多页入口；`electron/main.cjs` 挂 `attachDesktopStage(win)`；`electron/media.cjs` 加 `desktop` 动作与窗口排除；`src/media.ts` 加 `setDesktopStage`；`src/MediaRoom.tsx` 加按钮、发快照、接命令。

#### 为什么必须复用 `.media-room.is-expanded` 那三层外壳

`src/styles.css` 里 grep `media-theater|theater-screen|template-collage` **零命中**，放映的全部样式在 `src/skin-bold.css`。而 `.media-theater .template-collage` 那一条同时给了八个颜色令牌的兜底值和 `position / inset / container-type: size`。**少了 `.media-theater` 祖先，版式的容器查询单位（cqw）直接失效**——所有按 cqw 定的字号会退回浏览器默认值。

所以桌面窗的 DOM 照抄那三层，并且带上 `is-expanded`：全屏那套 `position: fixed` + 视频铺满的规则就免费拿到了。

#### 通道：`src/desktop-bridge.ts`

和 `focus-bridge.ts` 同一个形状——页面 sandbox、没有 preload，所以两边各自把东西挂到 `window` 上，主进程定时搬。

| 名字 | 谁写 | 谁读 |
|---|---|---|
| `__ravenStageSnapshot` | 主窗口 | 主进程 → 转给桌面窗 |
| `__ravenDesktopPaint` | 主进程调 | 桌面窗 |
| `__ravenDesktopDrain` | 桌面窗 | 主进程 |
| `__ravenStageCommand` | 主进程调 | 主窗口 |
| `__ravenStageClosed` | 主进程调 | 主窗口（按钮复位） |

三条实现上的决定：

1. **快照里连 `palette` 一起传**。取色对视频要**解码一帧**，桌面窗再取一次就是第二份解码；而且两次抽帧有随机性，颜色可能不一样。传几十字节的颜色数组既省一次 4K 解码，又保证两边配色完全相同。
2. **`listenStageCommand` 用覆盖式注册，不是数组**。放映页同时只有一只，多个处理器会让一次点击被处理两遍——切歌会跳两首。
3. **drain 换新数组，不原地 `splice`**。返回的就是原来那个引用，原地清空会把要交出去的东西一起清掉。`tests/desktop-bridge.test.ts` 有一条专门守这个。

#### 两处必须排除桌面窗的地方

- `electron/media.cjs` 的 `browser-window-created`：原来只排除 `mini.html`，现在要连 `desktop.html` 一起排除。**`MediaBridge` 只有一个 `target`，谁最后加载完谁抢走**，主窗口的选文件、全屏就没人处理了。
- 顺带把 `MediaBridge.start()` 改成「已经在跑就不再认领 target」。原来是先赋值再判断 `timer`，所以第二个窗口一定会把 target 改掉。

#### 摆放与生命周期

- 用**主窗口所在那块屏**的 `display.bounds`，不是 `workArea`：这是一块画面，任务栏压在上面是可以接受的，真的铺满才有「桌面上的画」的感觉。
- `skipTaskbar: true` + `showInactive()`：亮出来但不抢焦点，用户点完还能继续在主窗口里操作。
- `backgroundThrottling: false`：切到别的程序上画面不能冻住。
- 关窗时主进程调 `window.__ravenStageClosed()`，控制条那颗按钮回到未按下——不然按钮一直亮着而画面其实没了。

#### 探针 `tools/probe/desktop-stage.cjs`

一次跑完验五件事，实测全绿：

```

desktop.matchesDisplay true  1920×1080 == display.bounds（不是 workArea）
stage.ready true             .template-collage 在，canvas 1920×1080
stage.canvas/bar/panel/disc  与主窗口逐块一致（bar 1210×274、panel 615×602、disc 619×619）
stoneAfterClickOnDesktop jade  在桌面窗点胶囊 → 主窗口石纹跟着换
pressedAfterClickOnDesktop true

closed.windowsLeft 0         收回后窗口真的没了

```

**判据为什么要看 `outbox` 有没有被清空**：`MediaBridge` 被抢走时不会报错，只会让主窗口的 outbox 一直攒着没人取。往 outbox 里压一条 `ping`，等 900ms 看它归零——归零就说明还是主窗口在被服务。


### 9.21 透明模式：桌面壁纸直接透上来，组件自己往上加

#### 与 Folia 的关系：选的是它两条路里的第二条

| | Folia 的「壁纸模式」 | Folia 的「透明背景」（我们做的） |
|---|---|---|
| 窗口在哪 | `SetParent` 到 WorkerW，**在桌面图标之下** | 普通窗口，浮在桌面之上 |
| 壁纸还能看见吗 | 看不见——那扇窗取代了壁纸 | 看得见，透过透明区域 |
| 能点吗 | 物理上收不到鼠标，要靠 Raw Input 旁路注入 | 能点，和普通窗口一样 |
| 代价 | 几千行旁路 + 多屏/DPI/全屏处理 | 桌面图标在透明区域里点不到 |

用户要的是「能用桌面上正在跑的场景壁纸」，第二条就够，第一条的代价完全不必付。

#### 四个坑（全是探针抓出来的，不是想出来的）

1. **`.media-theater` 和 `.theater-screen` 各有一条黑底。** 这条最要命：skin-bold.css 给全屏那套写了 `.media-room.is-expanded .media-theater { background: #000000 }` 和 `... .theater-screen { background: #000000 }`（都是 0,3,0）。桌面窗为了复用 cqw 单位，套的正是 `is-expanded` 三层外壳，于是整块画面被这两层盖住——**用户看到的是纯黑，不是壁纸**。修法是在 `src/desktop.css` 里补 `.media-room.is-expanded.desktop-stage .media-theater / .theater-screen { background: transparent }`（0,4,0，且 desktop.css 最后加载）。

   **探针为什么会漏**：第一版只量了 `html` / `body` / `.desktop-stage` / `.template-desktop` 四层，四层全绿，就以为做成了。中间那两层根本没进采样。现在的写法是从内容沿父节点一路爬到 `html`，逐层报 `backgroundColor` 与 alpha，输出 `opaqueLayers`——**空数组才算过**。教训：验「透不透」要把从窗口到内容之间的每一层都遍历一遍，不能挑自己记得的那几层。

2. **`:root` 的底色盖不住。** 原版 `src/styles.css` 第一行就是 `:root{...background:#eae9e4}`。桌面窗里写 `html, body { background: transparent }`——`:root` 是伪类（0,1,0），`html` 是标签（0,0,1），**特异性更低，盖不住**。实测 `htmlBg` 一直是 `rgb(246,245,242)`，整块桌面被糊掉。修法是也写 `:root`，靠「后加载的赢」。

3. **透明模式下叠加层会重影**（**这一条在合并之后已经不成立了**，留作记录）。当时 `OverlayLayer` 里的时间、标题、日期、番茄钟，和组件里同名的四块**画在同一个位置**，屏幕上出现两份时间。当时的取舍是「透明模式只留一条加东西的路」，用 `template === 'desktop'` 把 `OverlayLayer` 挡掉。后来图层合成一套（见下），同名的四件只画一遍，那个开关就删掉了。

4. **`setPointerCapture` 抛错会吃掉 `setDrag`。** 合成事件下它抛 `NotFoundError`，不包 `try/catch` 的话后面那句 `setDrag` 一起没执行，现象是「按下去整块一动不动」。

#### 松手之后不许弹回原位（用户 m12322）

用户原话：「我发现在桌面上调整小组件，就会先弹回原位再瞬移到我指定的位置」。

**成因**：桌面窗是另一个渲染进程，松手以后位置要绕一圈才回来——发命令 → 主进程
200ms 轮询取走 → 主窗口落盘 → 再发快照 → 主进程再推回来。这一整圈里桌面窗手上的
还是旧坐标，于是先弹回原位、等快照到了再瞬移过去。主窗口自己是同步的，所以那边
一直没这个毛病——**是「另一头不是同一个进程」才让它显形**。

**修法**：`LayerStack` 里新增一份 `settling`——松手时先把新位置钉在那里
（`layers.ts` 的 `settleAt`），渲染时按 `live ?? settling ?? 存档` 取值；
等上层送上来的那份对上了（`settleConfirm`，容差 0.001），才把那一条从
`settling` 里摘掉。`settleConfirm` 在没东西可摘时**返回同一个引用**，
否则它跑在 `useEffect` 里会每次都触发一次重渲染。

**顺手修掉的隐患**：原来 `onUp` 把 `onChange` 写在 `setLive` 的 updater 里。
updater 必须是纯函数，StrictMode 下会被调用两次——桌面窗那边就会发两条命令出去。
改成坐标同时留一份在 ref 里，松手时从 ref 读。

**探针判据**（`tools/probe/desktop-drag-settle.cjs`）：在桌面窗里拖时钟 160/90，
**从 `pointerup` 那一刻起逐帧（rAF）记录位置**，统计「落回原位 8px 以内」的帧数。
只量松手后某一时刻不够——瞬移发生在中间那一两帧里。

实测：

| | 落回原位的帧数 | 最终位置 |
|---|---|---|
| 摘掉修复 | **100 帧**（约 300ms 停在原位，然后瞬移） | 到是到了，但先弹回去了 |
| 修好之后 | **0 帧**（449 帧全停在新位置） | `(467,195) → (627,285)` |

探针还要注意一件事：**必须 `attachDesktopStage(win)`**。桌面窗那个轮询器住在
`electron/desktop-stage.cjs` 里，不 attach 的话主进程不会去取快照，桌面窗永远是
`desktop-stage-blank`——第一版就是这么量到 `no-clock` 的。

#### 「完全一套」是怎么合的（用户 m12005）

用户原话：「加组件和叠加元素能完全一套吗」。

能。两套展开只看三处差异，行为本身完全一样（都是浮在画面上、按住能拖、松手才落盘）：

| | 合并前·叠加元素 | 合并前·组件 |
|---|---|---|
| 存档结构 | `Record<id, { on, spot }>` | `[{ id, spot, scale }]` |
| 图元表 | 四件（时间/标题/日期/番茄钟） | 六件（多了唱片、曲目） |
| 渲染样式 | `.overlay-*` + `.ov-*`，深色小字 | `.dw-*`，压在壁纸上的白色大字 |

**核心简化是删掉 `on` 字段。** 「在列表里」就是显示，「不在」就是没加——这两件事本来就同一件，两处各存一份只会对不上。代价是删掉再加回来会回到默认位置，可以接受：位置是拖出来的，再拖一次不费事。

**旧存档怎么搬家。** `readLayers(raw, overlayRaw, widgetRaw)` 三级优先：新键 → 两份旧键搬家 → 默认值。搬的时候**叠加元素那份优先**（它跟用户更久，位置是他拖惯的那个）。注意「旧键存在但是空的」与「压根没存过」必须分开——前者返回空数组，后者才给默认那两块，否则用户全删了刷新又冒出来。

**皮肤不进数据。** `LayerStack` 按 `skin` 切两套类名，拼贴/照片那套 `.overlay-*` 与 `.ov-*` 一个字没动（硬约束：拼贴版式外观不许改）。为此补了两条新样式 `.ov-now` 与 `.ov-disc`——唱片与曲目原来是透明皮肤独有的，合并之后拼贴/照片也能加。

**三处都验过**：`tsc` 0 错、`npm test` 284 项（新增 `tests/layers.test.ts` 20 条，旧的 `tests/widgets.test.ts` 与 `media.test.ts` 里那三条叠加元素测试删掉）；`layers-button.cjs` 两种版式菜单都是六项、全屏拖动存档 `(0.31,0.22) → (0.388,0.303)`；`desktop-stage.cjs` 桌面窗里拖组件 `wroteBack: true`；`desktop-alpha.cjs` 透明 `share 0.9986`。

- 每块图层右下角一颗手柄（`.layer-grip`），悬停才显形——六块各挂一颗常驻圆点，
  铺在桌面上就是图钉阵。
- 手感用 **「到中心的距离比」** 而不是「拖了多少像素」（`layers.ts` 的 `scaleFromDrag`）：
  元素中心不动，往外拖就是变大，比值正好是用户看到的那个东西。用像素差会有个说不清的
  基准——拖 100px 是几倍？
- **字号真的会乘上去**：照片/透明两套的 `.ov-*` 与 `.dw-*` 改成
  `calc(clamp(...) * var(--oscale, 1))`。外层 clamp 是「这个窗口该多大」，`--oscale` 是
  「用户自己调了多大」，**相乘**才不会换窗口就把调整打回原样。透明皮肤本来就是 `--wscale`，
  一套变量两处用。
- **拼贴不传 `scalabe`**，并且永远按 1 倍渲染。只做前半句不够：不给手柄却让它跟着照片
  版式调过的倍率一起变大，用户看到的是「我没动它，它自己变了」，而且在那里没有恢复手段。
- 松手先钉住倍率再上报（`settleScale` / `settleScaleConfirm`），与位置那套同理——
  桌面窗是另一个进程，不钉住就会先弹回原大小、再跳到新大小。

整个消失。探针第一次跑就量到「照片版式取不到 `.ov-clock`」。修法是补一句

#### 版式切换：白底滑块滑过去

新建 `F:\Vibe-bold\src\TheaterTemplates.tsx`。做法照抄唱片柜的筛选胶囊：一颗绝对定位的白底 `.template-marker`，位置由 JS 量出来写进 `--marker-x` / `--marker-width`，CSS 负责过渡。

两个必须注意的点：

- **量 `offsetLeft` / `offsetWidth`，不量 `getBoundingClientRect()`。** 全屏时外层 `.view-stage` 带 `transform: scale()`，`getBoundingClientRect()` 回来的是缩放后的尺寸，滑块会比按钮窄一圈。
- **第一帧不许有过渡。** `data-ready` 初值为空，量完第一遍后在 `requestAnimationFrame` 里才置 `'true'`；否则首屏滑块会从最左边飞过来。

```css
.theater-templates > .template-marker {
  position: absolute; left: 0; top: 3px; bottom: 3px; z-index: 0;
  width: var(--marker-width, 0px);
  transform: translateX(var(--marker-x, 0px));
  border-radius: 999px; background: #fff; pointer-events: none;
  transition: transform 380ms cubic-bezier(0.3, 1.28, 0.48, 1),
              width 380ms cubic-bezier(0.3, 1.28, 0.48, 1);
}
.theater-templates:not([data-ready='true']) > .template-marker { transition: none }
.theater-templates > button.on { background: transparent; color: #101010 }
```

#### 比例照参考图量，别凭手感

`.tools/ref-ticket/ref-1.jpg` 量出来：整张 **1124×563**（≈2:1），画面 **69.2%**，票根 30.6%，画面本身 1.441。量法在 `.tools/ticket-props.cjs`。

**这个数量了五版才对**，四个坑一个比一个隐蔽，全是「看起来在量、其实在量自己」：

1. **扫描窗口的边界不能当被测物的边界**。x 起点写 700，量出来的 `panel.x` 就恒等 700——那是我给的窗口左界，不是票根的左缘。
2. **判别式必须互斥**。票根上有深色字（`L<190`），把「深色=照片」的判据一起命中了，照片的 bbox 一路吃到票根里。
3. **单像素命中不算数**。票根那行红字饱和度高，逐像素「或」起来会让照片右界吃到 x=1000。改成**逐列投票**（该列满足条件的像素占比超过阈值才算这一列属于照片），缝两侧占比从 0.65 直接掉到 0.05，分界干净没有灰带。
4. **页脚水印会撑高 bbox**。抖音号是白的，正好落在「纸色」判据里，高度一路撑到图底。扫到 y=1660 就停。

实测判据：页面纸底 `S≈29 / L≈223`；票根纸 `S≈21 / L≈231`；照片块 `S>40 或 L<190`。

#### 一列，不是 auto-fit

外壳 `.portrait-shell` 只有 760 宽（`max-width: 760px`）。四列时每张票不到 160px，票根里那行日期挤成竖排；两列能读，但票就没有票的分量了。

```css

```

用户 m14515 之后改成一页六张：

#### 画面按 16:9 完整显示，票根因此更细长

> 「要不要把票根做的再细长一些，我感觉是不是比原样例还粗一些，或者至少应该按 16：9 把画面展示全了」

#### 撕是用户的手，不是定时器

`src/ticket-tear.ts`（纯逻辑，8 条测试）：

```ts

export function tearProgress(dy: number, panelHeight: number): number
export function shouldTear(dy: number, panelHeight: number): boolean
```

`TicketStage` 用 `--pull` 一个数同时驱动票根的位移、旋转、透明度——三者同源才不会各走各的。没撕够弹回 0（`transition` 自己收），撕够才进 `burning`。

拖拽只绑在 `.ticket-lift-panel`（右半边）上：在画面上拖不撕。探针对照过——`DRAG_ON_SHOT` 之后 `stage` 仍是 `idle`。

#### 灰烬：位置由散列算，样式只管接三个数

`ashParticles(seed, 28)` 给出归一化的 `x/y/dx/dy/rot/size/delay`，三路 FNV-1a（`${seed}#${i}` / `@` / `!`）。**同一张票每次同灰**，换一张不同——用 `Math.random()` 的话关掉再打开就是另一把灰。

方向：`dy` 恒为负（往上飘），越靠下的灰片飘得越高、起飞越早——纸是先从下沿断的，顶边最后散。这两个方向我一开始写反了（`top = 1 - down`），测试连挂三次才修对。

CSS 只做一件事：把 `--ash-x` / `--ash-y` / `--ash-rot` 接进关键帧，颜色 900ms 从 `#4a443a` 走到 `#b6ad9d`（越飘越淡）。

#### 画面飞进放映台：落点是量出来的

烧完（900ms）才飞，飞完（520ms）才 `onPick`——提前换台的话，画面还没落地幕布上已经先亮了。

**落点按版式选**（用户 m14515 第 2 条：「这个视频放到放映机的动画位置是错的，而且这个模式对应位置也不一样啊，你得按每个模式单独做」）。三种版式的画面块压根不是同一个矩形，实测（窗口 1264×835）：

```

photo    screen 680×383   block null                            photo 680×383
desktop  screen 680×383   block null                            photo null（压根没画面）
```

原来一律飞 `.theater-screen`，所以拼贴非全屏时飞偏、还飞大一圈。改成表驱动：

```ts

```

**第二个错在 `flightOf` 自己**：它原来返回中心点差，而 CSS 是 `transform-origin: 0 0` + `translate(...) scale(...)`——缩放绕左上角做，左上角只受 translate 影响。用中心点差会被缩放放大，实测拼贴落点偏左 **137px**。改成左上角差之后三种版式的误差是 0 / 0 / 0（宽高差 ≤0.4px，来自 `scale` 保留三位小数）。

顺便记一条探针的教训：**飞行途中不能读画面的绝对矩形**。飞行是 520ms 的 CSS transition，那时候 `getBoundingClientRect()` 返回的是已经平移缩放过的中间态，再 `+ dx` 等于加了两遍，量出一堆假的 -96px。正确做法是 idle 阶段先记一份 `from`，之后只读 `--fly-x/y/scale` 三个变量自己算落点。

#### 三个只在真机上才暴露的坑

1. **纸色令牌要挂在两个宿主上**。`.ticket, .ticket-lift { --paper: …; --paper-sheet: … }`。浮层不是 `.ticket` 的后代，只写在 `.ticket` 上会让 `.ticket-lift` 的 `background: var(--paper-sheet)` 解析失败退回透明——整张票变成一块透出暗幕的灰玻璃，字还压在暗底上。探针截图里看得很清楚（第一次 `ticket-lift.png` 就是灰的）。
2. **提示不能挂在会转的票根上**。`「按住票根往上撕」` 原来在 `.ticket-lift-panel` 里面，票根跟着 `--pull` 转，提示跟着晃，而且压在条码上读不出来。挪到票下面（`bottom: -26px`、白字带 `text-shadow`）。
3. **那层纸自己也要烧掉**。`.ticket-lift-panel` 烧的是**字**，如果纸留在 `.ticket-lift` 的 `background` 上，看到的就是「字烧没了、白纸还在」——像把文字层删掉，不像把票烧掉。
   纸要挪到 `.ticket-lift::before` 上才烧得掉：渐变色 `transition` 不了，`opacity` 可以。`::before` 用 `z-index: -1` 垫在画面与票根下面，所以 `.ticket-lift` 必须 `isolation: isolate`——不然它会跑到自己的 stacking context 外面，连暗幕都可能被一起盖掉。
   飞的时候也别再写 `background` / `box-shadow`（原来的规则里有），那会把纸盖回去，变成「整张票在飞」而不是「只剩画面在飞」。

### 9.23.1 一张票是两块纸，不是一整块（用户 m14823）

用户原话：「这个样式值的是票根的形状和样式，具体来说就是图案部分上下应该是直的
没有锯齿这种意思，其他的形状和样式你自己理解」。

放大参考图（`.tools/edge-top.png` / `edge-seam.png` / `edge-right.png`）看出来的事：

- **照片块只左右两条边有齿孔，上下是一刀切平的**。原来四边都挖，齿孔把照片切成了邮票。
- **票根块右缘是一串向外鼓的半圆**（波浪），不是挖进来的缺口；它在页面底色上留下投影。
- 两块纸各自成形、中间留一道缝，撕线就在那道缝里。做成一整块的话，齿孔无论怎么挖
  都只是「一张纸上的花纹」——这是我第一版做错的地方。

做法：

```css
/* 照片块：两层径向遮罩，只留左右 */
mask-image:
  radial-gradient(circle var(--edge-radius) at 0 50%, #0000 var(--edge-radius), #000 calc(var(--edge-radius) + 0.4px)),
  radial-gradient(circle var(--edge-radius) at 100% 50%, #0000 var(--edge-radius), #000 calc(var(--edge-radius) + 0.4px));
mask-size: 100% var(--edge-step), 100% var(--edge-step);
mask-repeat: repeat-y, repeat-y;
mask-composite: intersect;

/* 票根块：一层矩形 ∪ 一列圆心压在右边界上的圆，只留右半 */
mask-image:
  linear-gradient(#000 0 0),
  radial-gradient(circle var(--edge-radius) at var(--edge-radius) 50%, #000 var(--edge-radius), #0000 calc(var(--edge-radius) + 0.4px));
mask-size: calc(100% - var(--edge-radius)) 100%, calc(var(--edge-radius) * 2) var(--edge-step);
mask-position: left top, calc(100% - var(--edge-radius) * 2) top;
mask-repeat: no-repeat, repeat-y;
mask-composite: add;   /* 并集：缺一层就只剩纸或只剩圆点 */
```

三个只在真机暴露的坑：

1. **`box-shadow` 会被 mask 一起裁掉**。两块都带遮罩，阴影只剩一圈没有阴影的硬边，
   必须换成 `filter: drop-shadow(...)`；连 hover 与当前张的高亮也得跟着换写法
   （当前张改用 `inset` 内描边）。
2. **令牌要跟着扩**。`--paper-sheet` / `--edge-radius` 原来只定义在 `.ticket` 上，
   浮层 `.ticket-lift` 不是它的后代，变量解析失败会静默退回透明——第一版整张票是灰的，
   透出暗幕。现在令牌块写成 `.ticket, .ticket-lift, .ticket-panel, .ticket-lift-panel`。
3. **浮层的齿要大一圈**（`--edge-radius: 5px / --edge-step: 20px`）。放大之后还用小齿，
   看着像一圈灰点。

浮起来那张还要单独排一遍：它比列表里那张高得多（画面按 16:9 撑），条码上的
`margin-top: auto` 会把剩下的空白一口吃掉，全堆在中间那一段，看起来像漏排。
浮层里改成 `justify-content: space-between` 并把条码的 `auto` 撤掉——
`auto` 外边距的优先级高于 `space-between`，两个都在就只有前者生效。

### 9.23.3 纸纹是 SVG 滤镜，不是贴图（用户 m14823）

用户原话：「是不是还有一种纸张的纹理感滤镜，这个也得做出来」。

`src/paper.ts` 生成 `feTurbulence type="fractalNoise" baseFrequency="0.9"`（周期约 1.1px，
印刷纸的目数），然后**两步压对比**才像纸：

1. `feColorMatrix saturate 0` 先合成灰度——`feTurbulence` 三个通道各自独立，不先合成
   会得到彩色噪点；
2. `feComponentTransfer` 每通道 `slope 0.34 / intercept 0.83` 压到 0.5 附近的一小段，
   再 `feBlend mode="multiply"` 乘到纸色上。直接乘原噪声是满幅黑白噪点，纸上那是一层灰。

`feFuncA slope="0" intercept="1"` 必须钉死 alpha：`feTurbulence` 的 alpha 也是噪声，
不钉死整块纸会半透明（大理石那轮踩过同一条）。

宿主由 `MediaTickets` 挂在 `<body>` 上，不在票根里——放在被 `mask` / `overflow` 裁的
容器里，Chromium 会判滤镜引用失效、静默退回 `none`，没有任何报错。

### 9.23.4 探针：截图与坐标必须一次成对（踩了三次）

`tools/probe/ticket-look.cjs` 现在一次拍六张：列表首张、四种版式各一张、浮层一张。
三个坑都写进文件头了：

1. **先拍列表再点开浮层**：反过来的话暗幕已经盖上，裁出来的列表只剩一片磨砂。

3. **一次只滚一张**：先滚一圈把所有坐标收下来再逐张截，页面会停在最后一次滚动的位置，

## 10. 死路记录（**别再走**）

### 10.1 场景壁纸：整条线做了三轮，全部否决

用户最初想「接入壁纸软件」，最终是他自己说砍掉的：

> 「我要它的预览干嘛，如果做不了那干脆直接删了这个功能，只播放图片和视频吧」（m608408）

四条路都试过：

| 方案 | 为什么不行 |
|---|---|
| `PrintWindow(Progman)` | 只能拿静态缓存。藏图标层后连抓 12 次，MD5 全同 `4AD1D0BD`。WE 走 DX11 合成，GDI 读不到 |
| 抓 WE 自己的 `WPEDesktopDX11Window` | 全黑，方差 0.0 |
| `getDisplayMedia` 抓整屏 | **会把用户正在玩的游戏一起抓进来**（截图里出现过 Valorant）。`setContentProtection(true)` 只能让自己隐身，别人的窗口还在 |
| WGC（Windows Graphics Capture） | `CreateForWindow(Progman)` 建项成功，但 `IDXGISurface::Map` 返 `E_INVALIDARG`，建 staging 纹理在 .NET Framework 4 上反复崩 |
| 读 WE `config.json` 播原文件 | 场景壁纸的 `file` 指向 `scene.pkg` → 破图；`preview.gif` 虽是真动画（68 帧）但只有 192–300px 正方形 |

`scene.pkg` 的容器格式我解出来了（`uint32 sigLen | sig "PKGV0001" | uint32 count` + 逐条 `nameLen/name/offset/size`），但里面是 WE 私有 `.tex`（DXT/BC 压缩）+ GLSL 着色器，等于重写一个渲染器。

**当前状态**：功能整体删除，`scanWallpaper` 遇到非 video/image 的作品整件 `continue` 跳过。

### 10.2 其他不要重走的

- **`mask-composite: exclude`** 在这版 Chromium 上会把整块面板连同文字一起抹掉。
- **`clip-path: path()`** 只吃像素、不随容器缩放。
- **按「暗像素」找唱片**：会把壁纸背景算进去，量出假圆心。**判色分类（通道差）比明暗可靠**。
- **两处 `@media (max-width: 760px)` 把拼贴压成单列**：正式 exe 窗口 `innerWidth` 只有 666，这两条会让右列两轨变成 0px，**面板和唱片根本不渲染**。这个 bug 卡了三四轮。决策：版式固定比例，窗口小就整体等比缩小，**不改结构**。

   - 已按这条做：信息条右半栏的 Focus 番茄钟（`StageFocus`）。它只在专注页开着时有数字，没开时显示「未开始」——用户要求保留这个态（「保留未开始吧」，m03687），因为空出一块会让人以为渲染坏了。
2. **视频要统一，软件要实时。** 同一条（m01219）里说清了两套东西的用途差异：视频版式追求可批量复用，所以唱片不改照片铺满；软件里的唱片必须跟着「正在播放的那一张」走，实时性是它的价值。

### P3：`photo` / `frame` 版式的叠加层未验证

`RainLayer` 和 `OverlayLayer` 挂在 `.theater-screen` 里，**三个版式共用同一个挂载点**，理论上三套都有。但 `photo`/`frame` 的 CSS 没针对叠加元素调过字号和对比度，实际观感没验证。

### 12.3 这个环境特有的坑

- **`ops_bash` 里不能直接写 PowerShell 语法**（`Get-Process` 报 `command not found`）。要么写成 `.ps1` 再 `pwsh -File`，要么用 bash 语法。**探针现在不需要 ps1 了**，直接用上面的 `env -u` 一行式。
- **`pwsh` 内联 `node -e` 里写 `\"` 或中文常量必报 `Invalid string escape`**，一律写 `.cjs` 再 `node`。
- **`write` 工具对未读过的源文件报 `file has not been read`** → 先 `ops_read_files` 再写。
- **`edit` 对刚被 Node 脚本改过的文件报 `file changed since it was read`** → 重新读一次再 edit。
- **模板字符串（反引号包裹的）里不能再出现反引号**，即使是在注释里。会把字符串提前截断，报 `SyntaxError: missing ) after argument list`。定位方法：`node --check <file>`。
- **`ops_read_files` 显示路径时会转义反斜杠**（`F:\\Vibe-bold`），但文件里实际是单个 `\`。`edit` 的 `old_string` 要用单反斜杠，或者干脆用 Node 脚本按行号替换。

## 13. 协作教训（**这一节可能是最有用的**）

上一个对话在沟通上卡住了。我复盘出来的几条，希望你能避开：

### 13.1 「按 AE」= 一个像素都不许自己发明

我犯的最大的错：把 AE 里那个**不规则五边形面板**理解成「矩形挖了个圆」。他连着说了三次：

1. 「应该有尖角包住唱片」
2. 「不是嵌在面板里，那个面板本身就不是一个规则的形状」
3. 「而且不是面板被切，而是面板本身绘制的时候就是一个不规则的图形」

**如果他说「按 XX 来」，就去拿 XX 的原始数据，不要从截图反推。** 截图会有压缩、缩放、颜色偏差；而且我会把「视觉上像」当成「几何上对」。

这次真正的转折点是他让我导出 AE 数据，在那之前我一直在用「估算 + 截图对比」，每一轮都是错的方向。

### 13.2 每次改版式之前先数同名规则

这个坑我踩了至少五轮。`.tpl-words` 有 7 条同名规则，最后生效的是文件末尾那条，但中间那些 `position: absolute` 还在生效，所以「改了没反应」。

**改之前先跑一遍计数，改完再跑一遍确认只留一条。**

### 13.3 不要用「截图看着对」当验证

截图有延迟（`capturePage` 在图片解码后立刻拍会拿到还没上屏的那一帧），而且隐藏窗口不跑 rAF。**要量几何就用 `getBoundingClientRect()`，要验颜色就读像素**，别用肉眼。

### 13.4 他说「先别做了，告诉我你需要什么」

这句是信号：**他不是在催，是真的不知道该给什么了**。这时候正确的反应是立刻说清「我需要 X，因为 Y」，而不是继续试。

那次我问出来的是「AE 里能不能跑个脚本」，然后一切都通了。

### 13.5 他要的是「一起看」，不是「等指令」

他的原话：

> 「你要做的不是听我的指导，而是更频繁的告诉我你打算怎么做，为什么这么做而已」

但反过来也成立——**改了十几轮还没对，说明我在猜，而不是在看**。

### 13.6 一个具体的建议

如果你接着做版式，**第一件事应该是**：

1. 打开打包好的 exe
2. 切到放映页，加几张图
3. 截图
4. 和他的参考图并排放

如果差得远，**先把 AE 数据重新导一遍**（第 7.1 节），确认 `raven-shapes.json` 里的数字和现在 CSS 里的一致。别从我的中间结论出发。
