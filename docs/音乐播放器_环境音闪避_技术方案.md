## 一、项目定位

一个 Windows 桌面音乐播放软件。核心差异化的功能不是"播放音乐"，而是：

**在播放音乐的同时叠加用户自己上传的环境音（雨声、咖啡馆、风声等），并且环境音会根据音乐波形的强弱自动让位——音乐响时环境音压低，音乐安静时环境音恢复。**

这个效果在音频工程里的标准叫法是 **sidechain ducking**（侧链闪避 / 侧链压缩）。它和简单地把两个音轨一起播放有本质区别：后者会互相糊在一起，听感浑浊；前者让两路声音"轮流让位"，音乐清晰、氛围感还在。

**这个功能决定了一切技术选型。** 下面所有内容都是从"必须实时拿到音乐的 PCM 数据"这个硬约束推导出来的。

## 二、核心功能需求

### 必须实现

1. **音乐播放**：本地音频文件，常见格式（mp3/flac/wav/m4a/ogg）
2. **环境音叠加**：用户上传的音频循环播放，音量可调
3. **动态闪避**：环境音音量随音乐电平实时变化
   - 音乐响 → 环境音快速降低
   - 音乐安静/停顿 → 环境音缓慢恢复
   - 过渡必须平滑，不能有"抽气感"（pumping）
4. **可调参数**：闪避深度、灵敏度、恢复速度至少要做成用户可调的滑块
5. **完全本地**：音频数据不出本机，无网络请求

### 明确不做

- 不做音乐平台的账号接入（原因见第三节）
- 不做社交、不做云同步
- 不做移动端

## 三、技术路线决策（已定，不必重新论证）

### 3.1 接入在线音乐平台的方案已被否决

原本考虑过接入 QQ 音乐、网易云、Apple Music 等平台，让用户直接听在线曲库。**已核实并否决**，原因是所有平台都不提供原始音频流：

| 平台 | 现状 | 为什么做不了 ducking |
|---|---|---|
| 网易云音乐开放平台 | 个人开发者可入驻，有 AppID + PrivateKey，提供搜索、歌单、播放控制。但**音频流不开放**，且个人配额 100 次/分钟、严禁用于公开服务 | 拿不到 PCM，无法分析波形 |
| QQ 音乐 / 酷狗 / 酷我 | 走 TME Connect，面向音箱、车机、电视等硬件厂商，需商务谈判 + QPlay 认证送测，个人开发者无法接入 | 同上 |
| Apple Music | MusicKit JS / API 可用，需 $99/年开发者账号、Media ID + .p8 密钥签 ES256 JWT。但音频经 DRM 加密，由 Apple 自己的播放器输出 | 拿不到 PCM，且不支持无损 |

**结论：任何"接入平台 API"的路线都与 ducking 功能互斥。不要在这条路上继续投入。**

补充的工程理由：开源软件接入第三方 API 存在密钥问题。AppID/PrivateKey 绑在应用上，写进开源代码等于公开送人，配额会被刷爆；替代方案要么要求每个用户自己申请 key（门槛过高），要么作者自建中转服务器（违背"完全本地"定位，且带来成本与合规责任）。

### 3.2 已定方案：让音乐流经过本程序

三种可能架构的对比：

| 架构 | 能否做 ducking | 结论 |
|---|---|---|
| 两路独立播放，交给系统混音 | 不能 | 只能控制自己那一路，看不到另一路的电平 |
| 抓系统回环输出（WASAPI Loopback） | 能，但有致命缺陷 | 抓到的是**已被系统混合**的输出，会把程序自己播放的环境音也抓进去，形成反馈循环，导致闪避判断失真 |
| **音乐流经过本程序** | 能，最干净 | 波形和混音都在自己手里，无反馈 |

**采用第三种。** 具体又分两条腿：

- **本地文件**：程序自己解码播放，PCM 本来就在手上，最简单，优先支持
- **外部播放器**（用户想用 QQ 音乐、Spotify、foobar 等）：通过**虚拟声卡**把音乐路由进本程序

### 3.3 虚拟声卡路由的具体做法

```
[外部音乐播放器] → [虚拟声卡 VB-Cable 的播放端]
                        ↓
               [本程序从 CABLE Output 抓取 PCM]
                        ↓
        [分析波形 → 计算增益 → 与环境音混音]
                        ↓
                  [真实声卡 / 扬声器]
```

用户只需在音乐播放器里把输出设备切到 "CABLE Input (VB-Audio Virtual Cable)" 一次，之后由本程序接管。

**注意一个容易搞错的事实：** 由于音乐被路由到了虚拟声卡，用户是听不到它的——本程序必须把抓到的音乐**既转发到真实声卡、又做旁路分析**，而不是"只分析不转发"。这两件事要同时做。

**为什么不用 Windows 的按进程回环（Process Loopback）：** 那个 API 可以只抓某个进程的音频、天然绕开自己，但要求 Windows build 20348 以上（Win11 / Server 2022）。开发机是 Win10 22H2（19045），不支持。虚拟声卡是目前唯一稳的方案。

**虚拟声卡安全性：** VB-Cable 是音频驱动，与键鼠驱动无关，不影响鼠标指针，也不与游戏反作弊冲突。

## 四、信号流结构

```
                       ┌──→ 转发（原样送到扬声器）
音乐 PCM ──────────────┤
                       └──→ 旁路分析 → 包络 → 增益计算 → 平滑 → 增益曲线 g(t)

环境音 PCM ──→ × g(t) ──┐
                        ├──→ 相加 → 输出到扬声器
音乐 PCM（转发）────────┘
```

关键点：**音乐分支有两条**，一条原样转发（保证用户能听到歌），一条做旁路分析（只用来算增益系数，不影响音质）。

## 五、DSP 算法与参数

### 5.1 处理流程

按 **10ms 子块**推进（48kHz 下约 480 samples）：

1. **测电平**：对子块求 RMS
   ```
   rms = sqrt(mean(x²))
   level_db = 20 * log10(rms)
   ```
2. **算目标衰减量**（软拐点压缩，无 knee 的简化版）
   ```
   over = level_db - threshold_db
   if over > 0:  target_db = -over * (1 - 1/ratio)
   else:         target_db = 0
   target_db = max(target_db, max_duck_db)      # 衰减量设上限
   ```
3. **一阶平滑**（Attack 快、Release 慢，这是听感的关键）
   ```
   coeff = a_attack if target_db < env_db else a_release
   env_db += (target_db - env_db) * coeff
   ```
   按子块更新的平滑系数：
   ```
   a_attack  = 1 - exp(-sub_block_ms / attack_ms)
   a_release = 1 - exp(-sub_block_ms / release_ms)
   ```
4. **转线性并应用**
   ```
   gain = 10 ** (env_db / 20)
   环境音输出 = 环境音 * gain
   ```

### 5.2 推荐参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| 分析子块 | 10 ms | 太长反应迟钝，太短会抖动 |
| 阈值 threshold | -28 dB | 低于此电平不触发闪避 |
| 压缩比 ratio | 4 : 1 | 超过阈值的部分压到 1/4 |
| Attack | 15 ms | 音乐一响，环境音多久让开 |
| Release | 350 ms | 音乐安静后多久恢复 |
| 最大衰减 max_duck | -15 dB | 不要让环境音完全消失，留一点氛围 |
| Look-ahead | 15 ms | 提前量，见 6.3 |
| 环境音基础音量 | 0.6 | 相对音乐 1.0 |

### 5.3 可选的进阶优化

**分频段闪避（显著提升听感）。** 只对 200Hz–4kHz（人声、主旋律乐器所在频段）做闪避判断，环境音里的低频成分（雨声的底噪、风声）不跟着让位。实现方式：对音乐分支做 FFT 或带通滤波后再算 RMS。这一步是把"能响"和"好听"区分开的地方，建议二期做。

**双阈值 + 迟滞。** 避免电平在阈值附近抖动导致增益反复跳。进入闪避用 -28dB，退出用 -32dB。

## 六、实现中的三个坑（必须处理）

### 6.1 Release 必须慢且必须平滑

不做平滑的话，环境音会跟着鼓点一跳一跳，行话叫 **pumping**，听感极差，比不闪避还难听。一阶 IIR 平滑成本极低，必须加。

### 6.2 用 RMS，不要用峰值

峰值检测会被单个镲片、军鼓的瞬态带偏，导致环境音疯狂收缩。RMS 反映"响度"而非"瞬间尖峰"，更接近人耳感知。

### 6.3 必须加 look-ahead 缓冲

平滑本身带来延迟：音乐起音的第一个瞬态到来时，环境音还没来得及让开，会被硬压上去，产生"咔"的感觉。做法是把分析分支提前 10–20ms 读取（音频输出分支延迟同样时间），这样增益曲线在瞬态到来前就已经开始下降。这是广播级 sidechain 的标准做法。

实现上最简单的方式：音乐先写入环形缓冲，输出回调从缓冲读取时，分析读取的位置比转发读取的位置超前 look_ahead 个采样点。

## 七、参考实现（Python，可直接运行验证效果）

### 7.1 依赖

```bash
pip install numpy sounddevice soundfile
```

系统需安装 VB-Cable（https://vb-audio.com/Cable/，免费版即可）。

### 7.2 完整代码

```python
"""
音乐 + 环境音动态闪避 参考实现
用法：
  1. 安装 VB-Cable，把音乐播放器的输出设备设为 CABLE Input
  2. python ducking_demo.py ambient.wav
验证：播放音乐时环境音自动降低，暂停音乐时环境音恢复。
"""
import sys
import threading

import numpy as np
import sounddevice as sd
import soundfile as sf


# ---------- 环形缓冲：跨线程传递抓取到的音乐 PCM ----------
class RingBuffer:
    def __init__(self, size):
        self.buf = np.zeros(size, dtype=np.float32)
        self.size = size
        self.w = 0
        self.r = 0
        self.lock = threading.Lock()

    def write(self, data):
        with self.lock:
            n = len(data)
            end = self.w + n
            if end <= self.size:
                self.buf[self.w:end] = data
            else:
                k = self.size - self.w
                self.buf[self.w:] = data[:k]
                self.buf[:end - self.size] = data[k:]
            self.w = end % self.size

    def read(self, n, offset=0):
        """offset>0 时读取未来数据（look-ahead），不移动读指针。"""
        with self.lock:
            start = (self.r + offset) % self.size
            if (self.w - start) % self.size < n:
                return np.zeros(n, dtype=np.float32)
            end = start + n
            if end <= self.size:
                return self.buf[start:end].copy()
            k = self.size - start
            return np.concatenate((self.buf[start:], self.buf[:end - self.size]))

    def advance(self, n):
        with self.lock:
            self.r = (self.r + n) % self.size


# ---------- 侧链闪避核心 ----------
class Ducking:
    def __init__(self, fs, threshold_db=-28.0, ratio=4.0,
                 attack_ms=15.0, release_ms=350.0,
                 max_duck_db=-15.0, sub_block_ms=10.0):
        self.threshold_db = threshold_db
        self.ratio = ratio
        self.max_duck_db = max_duck_db
        self.sub = max(1, int(fs * sub_block_ms / 1000.0))
        self.a_att = 1.0 - np.exp(-sub_block_ms / attack_ms)
        self.a_rel = 1.0 - np.exp(-sub_block_ms / release_ms)
        self.env_db = 0.0

    def gain_curve(self, music, n):
        gain = np.ones(n, dtype=np.float32)
        for start in range(0, n, self.sub):
            end = min(start + self.sub, n)
            seg = music[start:end]
            rms = float(np.sqrt(np.mean(seg * seg) + 1e-12))
            level_db = 20.0 * np.log10(rms + 1e-12)

            over = level_db - self.threshold_db
            target = -over * (1.0 - 1.0 / self.ratio) if over > 0 else 0.0
            target = max(target, self.max_duck_db)

            coeff = self.a_att if target < self.env_db else self.a_rel
            self.env_db += (target - self.env_db) * coeff
            gain[start:end] = 10.0 ** (self.env_db / 20.0)
        return gain


def find_device(keyword, kind):
    for idx, dev in enumerate(sd.query_devices()):
        if keyword.lower() in dev["name"].lower():
            if dev.get(f"max_{kind}_channels", 0) > 0:
                return idx
    raise RuntimeError(f"找不到包含 '{keyword}' 的 {kind} 设备，请检查 VB-Cable 是否安装")


def load_ambient(path, fs):
    data, sr = sf.read(path, dtype="float32", always_2d=True)
    mono = data.mean(axis=1)
    if sr != fs:                      # 简单线性重采样
        n = int(len(mono) * fs / sr)
        mono = np.interp(np.linspace(0, len(mono) - 1, n),
                         np.arange(len(mono)), mono).astype(np.float32)
    return mono


def main(ambient_path):
    fs = 48000
    ambient_gain = 0.6
    look_ahead = int(fs * 0.015)      # 15ms

    cable_in = find_device("CABLE Output", "input")

    ring = RingBuffer(fs * 2)
    ducker = Ducking(fs)
    ambient = load_ambient(ambient_path, fs)
    pos = 0

    def in_cb(indata, frames, t, status):
        ring.write(indata.mean(axis=1).astype(np.float32))

    def out_cb(outdata, frames, t, status):
        nonlocal pos
        # 分析用未来数据（look-ahead），转发用当前数据
        music = ring.read(frames)
        side = ring.read(frames, offset=look_ahead)
        ring.advance(frames)

        chunk = np.empty(frames, dtype=np.float32)
        remaining = frames
        filled = 0
        while remaining > 0:
            take = min(remaining, len(ambient) - pos)
            chunk[filled:filled + take] = ambient[pos:pos + take]
            pos = (pos + take) % len(ambient)
            filled += take
            remaining -= take

        g = ducker.gain_curve(side, frames)
        mixed = music + chunk * g * ambient_gain
        np.clip(mixed, -1.0, 1.0, out=mixed)
        outdata[:, 0] = mixed
        outdata[:, 1] = mixed

    with sd.InputStream(device=cable_in, channels=2, samplerate=fs,
                        blocksize=480, callback=in_cb), \
         sd.OutputStream(channels=2, samplerate=fs,
                         blocksize=480, callback=out_cb):
        print("运行中。Ctrl+C 退出。")
        try:
            while True:
                sd.sleep(1000)
        except KeyboardInterrupt:
            print("\n已退出")


if __name__ == "__main__":
    main(sys.argv[1] if len(sys.argv) > 1 else "ambient.wav")
```

### 7.3 验证方法

1. 播放器输出设为 CABLE Input，随便放一首有鼓点的歌
2. 运行脚本，声卡里应该同时有音乐和环境音
3. **暂停音乐** → 环境音应在 0.3 秒左右逐渐恢复
4. **恢复播放** → 环境音应在几十毫秒内明显压低
5. 若出现环境音"一跳一跳"，是 release 太短；若音乐起音瞬间环境音没让开，是 look-ahead 不足

## 八、移植到 C# / NAudio 的要点

如果主程序是 C#，对应关系如下：

| Python | C# / NAudio |
|---|---|
| `sd.InputStream(device=cable_in)` | `WasapiCapture(cableInputDevice)` |
| `sd.OutputStream` | `WasapiOut(MMDevice, AudioClientShareMode.Shared, ...)` |
| `RingBuffer` | `BufferedWaveProvider`，或自建 `CircularBuffer<float>` |
| `sf.read` | `AudioFileReader` |
| `gain_curve` | 需自行实现（NAudio 无现成 sidechain） |
| 混音相加 | `MixingSampleProvider` |
| RMS 计算 | 手写，`NAudio.Dsp` 有 `EnvelopeDetector` 可参考 |

关键注意：

- `WasapiCapture` 的设备要选 **CABLE Output**（这是 VB-Cable 的录音端，也是输入设备）
- 输出用默认扬声器
- `DataAvailable` 回调里不要做重活，把数据丢进缓冲，在输出侧处理
- C# 里同样需要 look-ahead：分析读指针超前转发读指针 720 个采样（48kHz × 15ms）

## 十、一句话总结

**不要接音乐平台。核心架构是"音乐流经过本程序"，用虚拟声卡把外部播放器的音频引进来，自己做转发 + 旁路分析 + 环境音闪避 + 混音输出。** 算法的成败在三个细节：RMS 而非峰值、release 要慢且平滑、必须加 look-ahead。
